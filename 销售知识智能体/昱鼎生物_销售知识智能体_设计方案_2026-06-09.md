## 一、项目背景与目标

### 1.1 为什么要做

昱鼎生物已进入"证后商业化"阶段。前易安（前列腺癌尿液 RNA 三类证）上市后，销售团队面临三个核心挑战：

- 产品知识门槛高：三类证数据、临床证据、竞品差异、指南条款等信息分散在多处，销售难以快速掌握
- 医生提问越来越专业："你们和为真生物的区别在哪？""灰区人群的阳性预测值是多少？"——销售需要秒级查到准确答案
- 一线反馈无法沉淀：医生的质疑、拒绝理由、竞品信息分散在个人微信/口头沟通中，无法反哺研发和医学

### 1.2 一句话目标

**把昱鼎七年积累的研发资产（三类证数据、临床证据、竞品差异、FAQ），变成销售能随身调用的知识武器。**

### 1.3 核心用户

昱鼎生物一线销售人员（含医学事务、学术推广），服务场景覆盖拜访前准备、拜访中答疑、拜访后沉淀。

## 二、系统整体架构

```
┌──────────────────────────────────────────────────────────┐
│                     知识维护后台（Web）                    │
│  文档上传 │ 知识条目编辑 │ FAQ管理 │ 审核 │ 效果看板        │
└──────────────────────┬───────────────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────────────┐
│                      知识库引擎                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │ 文档解析  │  │ 向量索引  │  │ 语义召回  │  │ 答案生成  │ │
│  │(PDF/Docx) │  │(embedding)│  │(rerank)  │  │(LLM+RAG) │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
└──────────────────────┬───────────────────────────────────┘
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │飞书机器人  │ │ Web 前端  │ │ 反馈收集  │
   │(即时问答)  │ │(深度使用)  │ │(一线→知识)│
   └──────────┘ └──────────┘ └──────────┘
```

### 2.1 架构说明

| 模块 | 职责 |
|------|------|
| **知识维护后台** | 文档上传与管理、FAQ 编辑、内容审核、回答效果监控 |
| **知识库引擎** | 文档解析→向量化→语义检索→答案生成（RAG 流程） |
| **飞书机器人** | 销售在飞书群聊或私聊中 @机器人 自然语言提问，10 秒内返回准确回答 |
| **Web 前端** | 知识库全局搜索、分类浏览、话术生成、拜访报告模板 |
| **反馈收集** | 销售提交"一线遇到的新问题 / 竞品动态"，经审核入库，形成知识闭环 |

## 三、知识库内容设计（MVP 版）

### 3.1 覆盖范围

MVP 聚焦前易安产品线，后续扩展到旁易甄/膀胱癌→全产品线→全公司能力。

### 3.2 四大知识域

| 知识域 | 内容示例 | 形式 |
|--------|----------|------|
| **产品与证据** | 前易安三类证数据（灵敏度/特异性/NPV/PPV）、临床定位、指南收录情况、近万例验证概述 | 结构化字段 + 文档 |
| **竞品对比** | vs 为真生物核心差异清单、vs 传统 PSA 路径优劣、vs MRI 靶向穿刺场景区分 | 对比表 + 应答话术 |
| **FAQ 问答库** | 医生最常见的 50-100 个问题及标准回答（"灰区到底多少？""和直接穿刺比优势在哪？"） | 问答对 + 引用来源 |
| **拜访支持** | 按医院/科室的个性化拜访建议、产品培训资料、学术推广素材 | 文档片段 + 模板 |

### 3.3 知识来源

| 来源 | 类型 | 更新方式 |
|------|------|----------|
| 已有产品文档、注册材料、临床报告 | 存量导入 | 系统自动解析入库 |
| 医学/研发部提供 | 增量补充 | 通过 Web 后台提交，审核后发布 |
| 销售一线反馈 | 增量补充 | 销售在 Web 端提交新问题/竞品动态，审核后入库 |
| 飞书文档 / Confluence（如有） | 持续同步 | 接口自动拉取 |

## 四、双入口设计

### 4.1 飞书机器人（轻量即时问答）

**使用场景**：拜访中、路上、会议间隙，随时随地快速查

**交互特点**：
- 销售在飞书里 @机器人 直接问
- 输出控制在 200 字以内 + 来源标注
- 典型对话示例：
  ```
  销售：PSA 灰区的人群，前易安能减少多少不必要穿刺？
  机器人：根据中国多中心研究（WJSO 2024），PCA3 模型可减少约 35.3% 的前列腺穿刺，
          同时延迟约 5.8% 的高级别癌检出。[查看详情→]
  ```
- 支持追问和上下文延续

### 4.2 Web 端（深度使用）

**使用场景**：拜访前准备、拜访后报告、新员工培训

**功能模块**：

| 功能 | 说明 |
|------|------|
| **知识库搜索** | 全局搜索 + 按知识域分类浏览（产品/竞品/FAQ/拜访支持） |
| **话术生成** | 输入场景（如"三甲医院泌尿外科主任首次拜访"），自动生成 3 分钟开场白话术 |
| **拜访报告助手** | 输入"今天去了 XX 医院，医生问了 XX 问题"→ 自动归类 + 生成结构化汇报 |
| **知识贡献入口** | 销售可提交"一线遇到的新问题 / 竞品动态"，经审核入库 |

## 五、技术栈

| 层 | 方案 | 说明 |
|----|------|------|
| **大模型** | Claude / 通义千问 | 医疗场景语义理解能力强，中文友好 |
| **向量检索** | Chroma / Milvus Lite | MVP 用轻量方案，百万级文档够用 |
| **文档解析** | unstructured / 自研 parser | PDF、Word、飞书文档自动结构化 |
| **飞书机器人** | lark-cli / 飞书开放平台 | 直接调飞书消息 API |
| **Web 前端** | React / Vue + 轻量后端 | 单页应用，功能聚焦不花哨 |
| **部署** | 阿里云 / 腾讯云单机 | MVP 不需要 K8s，一台机器跑全部 |

## 六、MVP 交付范围与时间线

### 6.1 阶段一（0-1 月）：打地基

- 知识库引擎搭建（文档解析 + 向量索引 + RAG 问答管线）
- 前易安知识包整理入库（产品证据、竞品对比、初始 FAQ 50 条）
- 飞书机器人第一版上线（单轮问答）

### 6.2 阶段二（1-2 月）：可用版交付

- Web 前端上线（搜索、浏览、话术生成）
- FAQ 扩展到 100+ 条
- 拜访报告自动生成功能
- 2-3 名销售代表开始试用，收集反馈

### 6.3 后续扩展方向（MVP 验证后）

- 知识库扩展到旁易甄/膀胱癌产品线
- 接入 CRM 系统，关联拜访记录与知识使用
- 上线效果看板（高频问题 Top 10、人工介入率、用户活跃度）

## 七、知识维护机制

### 7.1 角色与职责

| 角色 | 职责 |
|------|------|
| **运营/市场** | 日常 FAQ 更新、话术模板维护、效果监控 |
| **医学事务** | 临床证据更新、竞品情报审核、回答准确性抽检 |
| **研发** | 产品参数变更同步、新管线知识补充 |
| **销售代表** | 提交一线新问题、竞品动态、话术反馈 |

### 7.2 更新流程

```
一线新问题/竞品动态
       │
       ▼  提交
┌──────────┐
│ 待审核队列 │
└─────┬────┘
      │  审核（医学/市场）
      ▼
┌──────────┐  ┌──────────┐
│ 更新 FAQ  │  │ 更新竞品库│
└─────┬────┘  └─────┬────┘
      │             │
      ▼             ▼
┌──────────────────────┐
│   知识库自动重新索引   │
└──────────────────────┘
```

### 7.3 质量控制

- 所有 AI 生成回答均标注来源文档
- 医学事务每月抽查回答准确性
- 设置"知识置信度"：高置信度自动回答，低置信度建议转人工
- 人工审核兜底：争议性问题由医学事务最终把关

## 八、验收标准与交付物

### 8.1 交付物清单

| 序号 | 交付物 | 验收标准 |
|------|--------|----------|
| 1 | 飞书机器人 | 销售用自然语言提问，10 秒内返回准确回答，含来源标注 |
| 2 | Web 知识库前端 | 全局搜索命中率 > 85%，话术生成可读可用 |
| 3 | 前易安知识库 | ≥ 100 条 FAQ、完整竞品对比包、产品证据摘要 |
| 4 | 运营文档 | 知识更新 SOP、飞书机器人使用指南 |
| 5 | 知识库引擎 | 文档解析→向量索引→RAG 问答全链路可运行 |

### 8.2 功能验收标准

| 验收项 | 标准 |
|--------|------|
| 问答响应时间 | < 10 秒（飞书机器人） |
| FAQ 搜索命中率 | > 85%（在 100+ 条 FAQ 中检索） |
| 答案准确性 | 核心产品数据（证号、临床指标）100% 准确，竞品对比信息经医学审核 |
| 来源可追溯 | 每条回答标注来源文档/段落 |
| 用户满意度 | 试用销售代表 NPS > +30 |
