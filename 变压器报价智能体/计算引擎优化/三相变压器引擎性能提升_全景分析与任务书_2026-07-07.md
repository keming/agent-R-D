## 第一部分：全景图——两条路径两种思维

### 一、核心命题

三相变压器计算引擎的核心矛盾是：

> **搜索空间过大导致计算慢**：10 层嵌套循环，Product 可达 10^6 ~ 10^16 量级，每次 `calculate()` 执行 1000+ 行代码，只有不到 1% 的迭代产出 FULL 结果。

解决这个问题，有两种完全正交的思维方式。从哪个角度切入，决定了你的方案长什么样。

### 二、两条路径

#### Path 1：入口缩小——搜索空间缩减

**核心思路**：在进入计算引擎之前，把搜索范围收窄，减少 `calculate()` 被调用的总次数。

**类比**：你有一片矿区，要在里面找金矿。Path 1 做的不是改进挖矿工具，而是**先看地质勘探报告，圈定可能的富矿区域**——只在最有希望的区域开挖，不挖整片山。

**技术实现（已落地）**：参数智能推荐系统（param-recommendation）

| 模块 | 说明 |
|------|------|
| 输入 | 22 维方案配置特征（容量、电压、线规、油道、并绕方式……） |
| 权重 | 方差归约（Variance Reduction）——统计每个特征对输出参数的解释力 |
| 匹配 | 4 个硬门槛（接线方式、低压线规、高压线规、频率）+ 加权相似度 |
| 输出 | 三层推荐策略（精准/标准/广泛），对应不同的推荐范围缩窄程度 |
| 回测 | 每次权重更新自动跑覆盖率验证，新旧版本对比 |

**典型效果**：铁心直径从 200~400mm（40 步）→ 350~390mm（4 步），WorkItem 总数减少 60~90%。

**关键认知**：这是一个**数据驱动的统计学习系统**。它不依赖物理公式，依赖的是「历史成功方案」的规律总结。效果随历史数据增长而增长。

---

#### Path 2：引擎提速——单次计算加速

**核心思路**：不改变搜索范围，而是让每一次 `calculate()` 内部跑得更快——通过调整执行顺序、提前淘汰无效路径。

**类比**：同样挖这片矿区，Path 2 做的是**改进挖矿工具**——让每一次铲土更快、更精准，少铲空矿。

**技术实现（你方案的方向）**：早起剪枝 + 阶段拆分

| 手段 | 说明 | 预期收益 |
|------|------|----------|
| 阶段拆分 | 将 `calculate()` 拆为 Phase 1~3，判定穿插其中 | 淘汰超标方案后无需继续跑后续阶段 |
| 早起剪枝 | P0/PK 前移判定、UK 粗估前置 | 20~30% 方案在 Phase 2 前被淘汰 |
| 计算复用 | 不重复计算 | ~10~20%（代码级） |

**关键认知**：这是**纯工程优化**。不改变物理公式、不改变计算结果，只改变到达结果的路径。风险极低，但收益有上限（单次 `calculate()` 加速 ~30~50%）。

---

#### 两条路径的关系

```
Path 1（入口缩小） × Path 2（引擎提速） = 相乘

举例：
  入口缩小 80%（1000→200 个 WorkItem）
  ×
  引擎提速 30%（100%→70% 计算量/个）
  =
  总加速 ≈ 7.14x
```

**两者的独立性和正交性**：
- 改入口不碰引擎代码，改引擎不改入口逻辑——互不干扰
- 可以各自独立开发、独立验证、独立上线
- 叠加使用效果最佳
