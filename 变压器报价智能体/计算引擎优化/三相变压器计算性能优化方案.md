# 三相变压器计算性能优化方案

---

## 一、现状

计算耗时正比于：

```
WorkItem 数 × L4~L9 迭代数 × 每次迭代的计算量

WorkItem 数    = 牌号 × 低压匝数范围 × 铁芯直径范围 × 油道组合数  ← 用户输入范围决定
L4~L9 迭代数   = LV线厚 × LV线宽 × LV层数 × HV线厚 × HV线宽 × HV层数 ← 线规表 + 约束决定
每次迭代计算量  = 叠厚 + 油道细节 + P0/PK/UK/温升/油箱/成本          ← 代码结构决定
```

当前代码在每个到达第 9 层的组合中（lines 1106-2366），一口气算完所有油道数据（半径、周长、散热面积 HDA、漏抗面积 OLFA/WLFA、油道 λ），约 575 行，然后才依次判定 P0 → PK → UK → 温升。判定和计算顺序不匹配——先全算了再判，判不过白算。

---

## 二、三类优化

### 第一类：提前淘汰

> 在昂贵计算发生之前，用低成本方式判断方案是否值得继续算。

#### 1.1 UK 粗估前置

**当前**：UK 判定在 line 1933，前面已经跑完了 575 行油道计算。

**改为**：Phase 1（半径链 + 周长）完成后，各段叠厚 ST 和内外周长 WINP/WOWP 已知，用 ~25 行粗估 UK，仅做上限单向淘汰：

```
粗估漏抗面积 = Σ(叠厚 × (内周长 + 外周长) / 6) + 主空道面积
粗估 LEAX    = 3.95 × NI × 粗估漏抗面积 × HZ × 1.03 / (HK × 10 × ET × 5000000)
粗估 UKR     = (WLVPK_直流 + HVPK_直流) / (P × 10)
粗估 UKK     = √(粗估 LEAX² + 粗估 UKR²)

if 粗估 UKK > UKMAX → 淘汰（偏小估都超标，真值必然超标，不会误杀）
```

粗估漏抗面积不含油道漏抗 OLFA 和 λ 修正，**系统偏小**，所以只淘汰超上限的，不因低于下限而淘汰。

**收益**：约 20%~30% 方案在粗估阶段被筛掉，省掉后续 Phase 2（~200 行）+ Phase 3（~400 行）。不改公式，仅 25 行新增代码。最坏情况全部通过，只多花 25 行。

### 第二类：范围缩减

> 从源头减少搜索空间，让 WorkItem 数和迭代次数直接下降。

#### 2.1 历史方案推荐输入范围

用户填好性能指标后，后端查询同规格历史成功方案，给出推荐范围。用户确认后填入。

**API**：

```
POST /api/scheme-config/range-suggestion
Request:  { capacity, hvVoltage, lvVoltage, frequency, connection, lvWireSpec, hvWireSpec, coreType, tankType }
Response: { suggested: { coreDiameterMin/Max, lvTurnsMin/Max, fluxDensityMin/Max, ... },
            confidence: "high" | "medium" | "low",
            sampleSize: N }
```

**查询逻辑**：从 `ThreePhaseSchemeRecord`（严格合规，`stage=0`）中筛选同容量 ±15%、同电压等级、同联结组别、同线材材质、同铁芯形式的记录，取最近 200 条。参数取 P5~P95 分位数，向外扩 15% 安全余量。

**confidence 分级**：

| 级别 | 匹配数 | 前端行为 |
|------|-------|---------|
| high | ≥ 20 | 绿色「推荐」 |
| medium | 5~19 | 黄色「参考」 |
| low | < 5 | 灰色「数据不足」 |

**前端**：「优化范围」步骤页加「智能推荐范围」按钮，弹窗对比 → 确认填入。

**收益**：铁芯直径从 100~400（60 个）缩到 180~240（12 个）= 5 倍，低压匝数类似，WorkItem 总数减少 20~30 倍。系统初期无历史时不生效，但随使用自增强。

**单相扩展**：参数化 `transformerType`，查各自的 `SchemeRecord` 表，逻辑复用。

### 第三类：计算顺序调整

> 重新排列计算和判定的执行顺序，把不依赖昂贵数据的判定提前，把昂贵数据的计算延后。

#### 3.1 油道计算按 P0/PK → UK → 散热分阶段

**当前问题**：油道 575 行中，半径（CR）、周长（WINP/WOWP）、散热面积（HDA）、漏抗面积（OLFA/WLFA）、油道 λ（OA）全部一起产出，然后才判 P0 → PK → UK → 温升。

**改为**：拆成四个阶段，判定穿插其中：

```
叠厚计算（60 行，不变）
    ↓
Phase 1: 半径链 + 周长（统一算，~150 行）
    各段 CR 递推 + calculateCircumference → WINP/WOWP
    在当前代码的 if 和 else 分支都算了，拆出来不新增任何计算
    ↓
P0 判定 → fail? continue  ← 省掉 Phase 2 + Phase 3
精确 PK 计算 + 判定 → fail? continue  ← 省掉 Phase 2 + Phase 3
    ↓
【UK 粗估前置（第一类 1.1）→ fail? continue  ← 省掉 Phase 2 + Phase 3】
    ↓
Phase 2: 漏抗数据 OLFA/WLFA/OA（仅算有油道的分段，~200 行）
    ↓
精确 UK 判定 → fail? continue  ← 省掉 Phase 3
    ↓
Phase 3: 散热面积 HDA（仅算有油道的分段，~100 行）
    ↓
温升 + 油箱 + 成本
```

**数据依赖分析**：

| 阶段 | 产出 | 依赖 | 可提前判定的指标 |
|------|------|------|----------------|
| Phase 1 | CR, WINP, WOWP | 叠厚 ST | — |
| — | CRGOG, CRGOPo | Phase 1 的外径 (HVO5CR+HVO5ST) | **P0** |
| — | WLVPK, HVPK, LVECL, HVECL, SL, 引线, HVLVPK | Phase 1 的周长 (WINP/WOWP) | **PK** |
| Phase 2 | OS, OLFA, WLFA, OA | Phase 1 周长 + 叠厚 | **UK** |
| Phase 3 | HDA | Phase 2 OS + Phase 1 周长 | **温升** |

Phase 1（半径 + 周长）**不依赖任何油道细节**，可以在 Phase 2/3 之前独立完成。PK 计算只需要匝长（由 Phase 1 周长得出）、截面积、电阻率——都不需要 OLFA 或 HDA。

**收益**：

|判定|淘汰率（估算）|省掉的计算|
|----|------------|----------|
|P0 + PK|~30%|Phase 2 (~200行) + Phase 3 (~400行)|
|UK 粗估|~25%|Phase 2 + Phase 3|
|精确 UK|~30%|Phase 3 (~400行)|

不额外增加任何计算。最坏情况（全部通过）总计算量不变，只有顺序变了。

## 五、待验证：线规粗步进扫 + 细步进精算

> **此优化不属于前述三类。它不是提前淘汰（粗扫不淘汰，是探路），不是范围缩减（不改输入范围），也不是顺序调整。核心思路是用步进大小控制搜索密度——先用大步进定位有希望的区域，再用小步进精细搜索。**

**本质问题**：粗扫是多出来的一遍计算，精算不能替代它。总计算量 = 粗扫 + 精算。如果粗扫通过率高、精算范围缩不窄，总计算量反而比原来大。

**思路**：L4~L8（四个导线尺寸循环）是 L4~L9 中迭代数占比最大的部分。先用步进 2 扫一遍（跑完整公式），找到通过的导线尺寸区域，再在缩窄的区域内用步进 1 精算。LVL、HVL 不跳（值太少）。

**粗扫**：线厚/线宽步进 = 2，跑完整计算。记录所有通过方案的导线尺寸索引。

**精算范围**：从粗扫通过的索引各向外扩 2：

```
lvT_min = max(0, min(通过的 ti) - 2),  lvT_max = min(size-1, max(通过的 ti) + 2)
// lvW、hvT、hvW 同理
```

**精算**：在缩窄范围内步进 = 1，跑完整计算。

**三种情况**：

| 约束松紧 | 粗扫通过率 | 精算范围 | 总计算量 vs 原始 |
|---------|-----------|---------|----------------|
| 紧（90%淘汰） | ~10% | ~15% | 6.25% + 15% ≈ 21%，省 79% |
| 适中 | ~50% | ~55% | 6.25% + 55% ≈ 61%，省 39% |
| 松（10%淘汰） | ~90% | ~95% | 6.25% + 95% ≈ **101%，更慢** |

**还有一个风险**：步进 2 跳过了相邻档位。如果全局最优恰好在被跳过的档位上，且该档位的两个相邻粗扫点都失败了（不进入精算范围），最优会被漏掉。

**建议**：暂不实施。第一阶段上线后，在 calculate() 里加统计埋点（仅收集数据不做过滤），收集粗扫通过率的实际分布和精算范围缩窄程度。数据回答之后再决定。
