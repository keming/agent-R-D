## 1. 产品定位

### 1.1 一句话定位

法拉迪变压器报价智能体，是面向销售、报价工程师、技术工程师的智能报价工作台。它把客户提供的非结构化需求，转成标准化变压器参数，再辅助匹配计算单、生成参数包，并逐步扩展到 BOM、成本、报价审批和知识沉淀。

### 1.2 产品不是做什么

第一版不要把它定义成“自动报价机器人”。

因为变压器报价涉及：

- 客户需求是否完整；
- 技术参数是否正确；
- 历史计算单是否可复用；
- 优化计算软件是否能对接；
- BOM 是否准确；
- 铜铝等物料价格是否过期；
- 报价是否需要审批。

所以它不能一开始就直接自动生成正式报价。

### 1.3 产品应该先做什么

第一版应该先做：

> 把客户需求可靠地变成技术可用的标准计算单参数包。

也就是先解决：

```text
客户需求看不懂、不完整、不标准、不好交给技术/软件计算
```

这个问题。

## 2. 目标用户与核心场景

## 2.1 目标用户

| 用户角色        | 主要诉求             | 在系统中的任务                |
| ----------- | ---------------- | ---------------------- |
| 销售人员        | 快速整理客户需求，减少反复问技术 | 上传需求、确认商业字段、查看客户澄清问题   |
| 销售工程师/报价工程师 | 形成可计算、可报价的参数包    | 复核参数、发起技术确认、导出参数包      |
| 技术工程师       | 保证关键工程参数正确       | 确认电压、损耗、阻抗、结构、套管、绝缘等字段 |
| 成本人员        | 确认 BOM 和价格依据     | 后续阶段确认成本、物料价格、汇率、毛利    |
| 审批人         | 控制正式报价风险         | 后续阶段审批报价单              |
| 管理员         | 维护系统基础规则         | 维护字段字典、同义词、计算单匹配规则     |

## 2.2 典型业务场景

### 场景 1：单相变压器多方案报价

客户给出：

- 75kVA；
- 13200/7200-120/240V；
- 60Hz；
- 全铝；
- 带 CSP；
- 普通油箱 400 台；
- 不锈钢油箱 100 台；
- 损耗 225/750 和 165/600；
- 阻抗 <2.5%。

系统要拆成多个报价方案行。

### 场景 2：三相变压器批量报价

客户给出多行需求：

- 50kVA，11/0.415kV，89 台；
- 100kVA，11/0.415kV，11 台；
- 200kVA，11/0.415kV，2 台；
- 300kVA，11/0.415kV，60 台；
- 1250kVA，33/0.415kV，10 台。

系统要拆成多个产品行，并继承公共参数。

### 场景 3：招标文件型需求

客户 Word 文档中既有型号列表，又有项目级技术要求，例如：

- IEC 标准；
- 苏丹户外环境；
- 50°C；
- 90% 湿度；
- ONAN；
- Dyn11；
- 质保；
- 测试报告；
- 铭牌图和总布置图。

系统要区分“项目级参数”和“产品行参数”。

## 3. 整体业务闭环

完整业务闭环如下：

```text
客户需求输入
→ AI 解析需求
→ 生成标准参数表
→ 检查缺失/冲突/风险
→ 销售确认商业字段
→ 技术确认关键工程字段
→ 生成计算单参数包
→ 匹配历史计算单
→ 优化计算软件生成计算单/BOM
→ 根据 BOM 测算成本
→ 生成报价草稿
→ 报价审批
→ 输出正式报价和客户文件
→ 沉淀为历史经验
```

这是一条完整链路，但不要第一版全部做完。应该分阶段建设。

| 模块       | 作用                      | 建设阶段 |
| -------- | ----------------------- | ---- |

| 澄清问题模块   | 自动生成需要问客户的问题            | 第一阶段 |
| 参数包模块    | 生成优化计算软件可用的标准参数包        | 第一阶段 |

## 5. 五阶段建设路线图

> 这一章只讲每个阶段的边界，不展开页面和字段细节。第一阶段的详细设计放到第 6 章以后。

## 5.1 第一阶段：需求解析与参数包智能体

### 阶段目标

把客户提供的需求，转成标准化、可确认、可导出的计算单参数包。

### 主要能力

- 上传客户需求；
- AI 解析参数；
- 拆分产品行；
- 识别项目级公共参数；
- 标记缺失/冲突/高风险字段；
- 生成客户澄清问题；
- 支持销售/技术确认；
- 导出计算单参数包。

### 阶段产出

- 标准参数表；
- 客户澄清问题清单；
- 技术确认单；
- 计算单参数包。

### 不做

- 不自动生成正式报价；
- 不自动生成 BOM；
- 不自动决定计算单复用；
- 不自动生成图纸。

---

## 5.2 第二阶段：计算单匹配与设计协同智能体

### 阶段目标

帮助销售和技术从历史计算单中找到可复用、可改型或仅可参考的设计。

### 主要能力

- 建立历史计算单索引；
- 匹配候选计算单；
- 输出 A/B/C/D 复用等级；
- 展示差异字段；
- 发起技术确认；
- 无匹配时生成新建设计任务。

### 阶段产出

- 候选计算单列表；
- 差异项报告；
- 复用/改型建议；
- 技术确认记录；
- 新建设计任务单。

### 不做

- 不让系统自动决定复用；
- 不让销售绕过技术确认；
- 不用单纯相似度代替工程判断。

---

## 5.3 第三阶段：BOM 成本与多方案报价智能体

### 阶段目标

在计算单或新设计完成后，读取 BOM，匹配物料价格，生成成本测算和报价草稿。

### 主要能力

- BOM 导入；
- 物料价格匹配；
- 价格有效期检查；
- 成本测算；
- 多方案成本对比；
- 报价草稿生成。

### 阶段产出

- BOM 成本表；
- 成本测算表；
- 多方案比较表；
- 报价草稿；
- 价格风险清单。

### 不做

- 不在价格缺失或过期时生成正式报价；
- 不直接复用历史报价作为当前报价；
- 不绕过成本人员确认。

---

## 5.4 第四阶段：正式报价审批与客户文件智能体

### 阶段目标

把报价草稿经过审批后，生成正式报价单和客户需要的技术文件。

### 主要能力

- 报价审批；
- 报价版本管理；
- 正式报价单导出；
- 技术参数表导出；
- 客户文件包生成；
- 报价条件和有效期管理。

### 阶段产出

- 正式报价单；
- 技术参数表；
- 报价审批记录；
- 报价版本记录；
- 客户文件包。

### 不做

- 未审批不得导出正式报价；
- 不允许修改后不留版本；
- 不允许报价单脱离参数包、计算单、BOM 和价格来源。

---

## 5.5 第五阶段：知识沉淀与持续优化智能体

### 阶段目标

把每次报价中的客户原文、人工修正、技术确认、计算单匹配、BOM 和报价结果沉淀下来，让系统越用越准。

### 主要能力

- 样例沉淀；
- 字段字典优化；
- 同义词维护；
- 历史报价分析；
- 计算单复用分析；
- 常见澄清问题沉淀；
- 异常报价预警。

### 阶段产出

- 字段字典迭代表；
- 规则优化记录；
- 历史报价看板；
- 计算单复用看板；
- 销售问答模板库。

# 6. 第一阶段详细设计：需求解析与参数包智能体

> 从本章开始，只详细展开第一阶段。后续阶段只保留路线图，等第一阶段确认后再展开详细 PRD。

## 6.1 第一阶段目标

第一阶段要让系统完成以下闭环：

```text
客户需求输入
→ AI 解析
→ 项目级参数 + 产品行参数
→ 缺失/冲突/风险检查
→ 客户澄清问题
→ 销售/技术确认
→ 计算单参数包导出
```

## 6.2 第一阶段用户流程

```text
1. 销售新建报价项目
2. 上传客户需求文件或粘贴邮件正文
3. 系统自动解析需求
4. 系统生成项目级参数和产品行参数
5. 系统标记字段置信度、缺失项、冲突项、高风险项
6. 销售确认商业字段
7. 系统生成需要问客户的问题
8. 技术确认关键工程字段
9. 系统生成计算单参数包
10. 报价工程师导出参数包或发给技术处理
```

## 6.3 第一阶段页面结构

第一阶段建议做 6 个页面或区域。

| 页面/区域  | 作用                |
| ------ | ----------------- |
| 报价项目列表 | 查看所有报价项目和当前状态     |
| 需求输入页  | 上传客户需求、粘贴邮件正文     |
| 解析工作台  | 左侧原文，中间参数，右侧风险和问题 |
| 字段确认抽屉 | 查看字段来源、置信度、确认状态   |
| 澄清问题页  | 自动列出要问客户的问题       |
| 参数包导出页 | 导出计算单参数包          |

## 7.3 解析工作台

采用三栏布局：

```text
左侧：客户原文/图片/Word
中间：项目级参数 + 产品行参数
右侧：缺失项、冲突项、澄清问题、确认任务
```

### 左侧：原文区

- 展示客户原始文件；
- 点击字段时高亮来源；
- 支持查看多附件；
- 保留邮件转发链和后续修改。

### 中间：参数区

分为两块：

1. 项目级参数；
2. 产品行参数。

### 右侧：风险和动作区

- 缺失字段；
- 冲突字段；
- 高风险字段；
- 需要客户确认的问题；
- 需要技术确认的字段；
- 参数包生成状态。

## 7.4 字段确认抽屉

点击任意字段，打开字段详情。

字段详情包括：

- 标准字段名；
- AI 解析值；
- 原文值；
- 来源文件；
- 来源位置；
- 置信度；
- 风险等级；
- 是否继承自项目级参数；
- 当前确认状态；
- 修改历史；
- 确认按钮。

### 字段颜色

| 颜色  | 含义       |
| --- | -------- |
| 绿色  | 已确认      |
| 黄色  | 待确认      |
| 红色  | 缺失、冲突、阻断 |
| 蓝色  | 继承自项目级参数 |
| 灰色  | 系统默认值    |

## 7.5 澄清问题页

系统把缺失或有歧义的字段整理成问题。

| 字段   | 系统生成的问题                    | 发送对象  |
| ---- | -------------------------- | ----- |
| 损耗   | 请确认空载损耗和负载损耗要求，或是否接受厂家标准损耗 | 客户    |
| 阻抗   | 请确认阻抗电压要求及允许偏差             | 客户/技术 |
| 绝缘水平 | 请确认高压侧绝缘水平要求               | 客户/技术 |
| 分接范围 | 请确认分接范围和分接开关类型             | 客户    |
| 套管数量 | 请确认高压、低压套管数量及出线方式          | 客户    |
| 执行标准 | 请确认执行 IEC、IEEE 或客户自定义标准    | 客户    |

支持一键复制为邮件或微信文本。

一个 QuoteItem 代表一个型号或一个报价方案。

## 9. 第一阶段关键规则

## 9.1 高风险表达规则

| 表达                  | 处理方式               |
| ------------------- | ------------------ |
| 无损耗                 | 标记为“客户未提供损耗”，不得填 0 |
| 225/750             | 在损耗上下文中解析为空载/负载损耗  |
| 13200/7200-120/240V | 保留原文，拆分需技术确认       |
| ±2×2.5%             | 标记为分接范围，不等同五档分接    |
| 全铝/全铜               | 默认绕组材料，但需销售/技术确认   |
| 终端型                 | 标记为结构字段，高风险        |
| 带 CSP               | 标记为关键附件，影响 BOM     |

## 9.2 阻断规则

以下情况不允许生成正式参数包：

- 容量缺失；
- 高低压缺失；
- 相数不确定；
- 损耗字段冲突；
- 阻抗字段冲突；
- 关键字段未技术确认；
- 客户要求和历史邮件更新内容冲突。

## 11. 第一阶段验收标准

## 11.1 单相 75kVA 多方案

系统应能：

- 识别容量 75kVA；
- 识别电压 `13200/7200-120/240V`；
- 识别频率 60Hz；
- 识别全铝；
- 识别带 CSP；
- 拆分普通油箱/不锈钢油箱；
- 拆分 225/750 和 165/600 两种损耗；
- 生成至少 4 个产品行；
- 标记阻抗 `<2.5%` 为关键字段；
- 识别后续邮件更新的绝缘和套管要求。

## 11.2 三相“无损耗”需求

系统应能：

- 拆分多个产品行；
- 正确继承全铜、Dyn11、分接范围、油枕散热片、温度计；
- 把“无损耗”标记为客户未提供损耗；
- 生成客户澄清问题；
- 不允许将损耗填为 0。

## 11.3 苏丹招标 Word 文档

系统应能：

- 生成 12 个产品行；
- 提取项目级参数：IEC 标准、苏丹环境、50°C、90% 湿度、户外、防腐、热带化；
- 每个产品行继承 50Hz、ONAN、Dyn11、阻抗 4%-5%；
- 200/300kVA 损耗正确匹配；
- 500/1000kVA 标记为“按 S9 待确认”。
