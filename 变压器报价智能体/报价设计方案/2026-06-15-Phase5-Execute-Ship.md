# 报价/方案智能体 · Phase 5: EXECUTE & SHIP（执行与交付）

> 本文档为技术设计方案的补充，基于 pm-skills 方法论，覆盖 Pre-Mortem、Red Team 攻击、用户故事、测试场景、Sprint 计划五个执行阶段关键环节。

---

## 5.1 Pre-Mortem —— 想象失败，反向推导

> **场景设定**：现在是 Phase 1 MVP 上线后第 14 天。产品**已经失败了**。请反向推导原因。

---

### 🐅 Tigers（高概率 × 高影响）—— 这些是我们最该担心的

#### Tiger 1: 历史项目数据质量差，方案匹配命中率低

| 维度 | 内容 |
|------|------|
| **根因链** | 法拉迪历史计算项目缺少结构化元数据（标签/分类/场景） → `search_calculated_projects` 检索依赖的向量检索语义理解弱 → 匹配到"看起来像但其实不相关"的项目 → 导入的数据偏差大 → 专家看到方案后直接驳回 → 销售觉得系统不靠谱放弃使用 |
| **Kill Criteria** | 前 20 次方案匹配中，专家审核通过率 < 50%，或专家平均修改时间 > 15 分钟（说明匹配到的项目偏差太大，还不如从零做） |
| **最廉价验证测试** | 拿 10 个真实历史项目需求作为测试用例，跑 `search_calculated_projects`，让 1-2 名专家盲评匹配结果的相关性打分（1-5 分），如果平均分 < 3.0 则此项假设失败 |

#### Tiger 2: 专家拒绝投入时间做回溯教学

| 维度 | 内容 |
|------|------|
| **根因链** | 专家日常工作忙碌 → "每周 2-3 小时回溯教学"听起来不多但实际被会议/紧急任务挤掉 → 知识库停留在冷启动的 50-100 份 → 覆盖场景有限 → Agent 遇到稍偏的场景就"不会" → 系统能力停滞不前 |
| **Kill Criteria** | 第 4 周结束时，专家实际累计投入 < 8 小时（目标 16-24 小时），或知识库新入库案例 < 20 条 |
| **最廉价验证测试** | 项目启动前先做 1 次 30 分钟的试录实验：找一个典型项目，让专家边翻项目边口述评审逻辑，录音→ASR→结构化→专家确认，测试整个录入流程的摩擦系数。如果专家明确表示"太麻烦"或 30 分钟内无法完成 1 个案例的录入，假设失败 |

#### Tiger 3: 电磁计算引擎 API 响应太慢，30 分钟出草案成空话

| 维度 | 内容 |
|------|------|
| **根因链** | `run_calc` 电磁优化计算单次耗时超预期（复杂方案可能 10-20 分钟） → 加上需求解析(3min)+匹配(5min)+BOM(5min)+报价(2min) → 总耗时 > 30 分钟 → 销售体感"没什么提升" → 与"传统 7-15 天"相比优势不够显著 → 无法形成使用习惯 |
| **Kill Criteria** | 在 Phase 1 测试环境中，对 5 个不同复杂度的典型需求跑端到端流程，P95 总耗时 > 60 分钟 |
| **最廉价验证测试** | 在法拉迪现有计算引擎上跑 10 个已完成项目的"重算"（用原输入参数），记录每次 `run_calc` → `get_calc_result` 的端到端耗时，取 P50 和 P95。如果 P95 > 15 分钟则需要重新评估"30 分钟出草案"的承诺 |

#### Tiger 4: 销售认为"又多了一个工具"而非"替代了工作"

| 维度 | 内容 |
|------|------|
| **根因链** | 销售已习惯打电话给技术部口头沟通需求 → 系统要求上传文件+填对话框 → 操作步骤反而比"打个电话"多 → 销售觉得"不如直接找人" → 使用率低 → Agent 无数据积累 → 恶性循环 |
| **Kill Criteria** | Phase 1 上线后 14 天内，销售主动使用次数 < 5 次（排除测试/演示），或首次使用后 7 天内无第二次使用 |
| **最廉价验证测试** | 上线前，找 3 名销售做"纸上模拟"：给他们一个假需求，让他们分别用"打电话找技术部"和"通过飞书机器人上传文件+对话补全"两种方式完成，记录每种方式的耗时和主观感受。如果 > 2/3 销售认为"机器人方式更麻烦"，假设失败 |

---

### 📄 Paper Tigers（看起来危险但实际可控）—— 不用太担心

#### Paper Tiger 1: LLM 幻觉导致报价数字错误

**为什么可控**：报价的核心数字（价格、损耗值、物料单价）走**规则引擎计算**，不依赖 LLM 生成。LLM 只负责需求解析、对话交互和文档生成。即使 LLM 出错，也只影响"自然语言描述"，不影响核心计算数字。加上 Phase 1 强制 HITL，错误数字过不了审核关。

#### Paper Tiger 2: 客户数据泄露/安全合规

**为什么可控**：系统设计为**私有化部署**，数据不出企业内网。已有 Agent Runtime 经过法拉迪安全审计。物料价格等敏感数据走内部数据库，不调用外部 LLM API 处理敏感字段。Phase 1 不对接外部 ERP，攻击面小。

#### Paper Tiger 3: 多品种小批量太杂，Agent 无法泛化

**为什么可控**：Phase 1 不追求泛化，只覆盖"已有历史计算项目的相似场景"。匹配不到就明确提示"无合适历史参考，请联系技术专家"，回退到人工流程。用"能做的做好，不能做的诚实告知"策略，避免强行出低质量方案。

---

### 🐘 Elephants（低概率但致命）—— 需要 Plan B

#### Elephant 1: 法拉迪电磁计算引擎在 Phase 1 期间未完成 API 化

| 维度 | 内容 |
|------|------|
| **概率** | 低（已有合同，且 CLI 工具已可调用） |
| **影响** | 致命——参数优化环节完全无法执行，方案只能做到"匹配+手动调整" |
| **Plan B** | 降级方案：Phase 1 先跳过自动参数优化，改为"匹配历史项目 + 差异分析标注 + 专家手动调参"。保持 Agent 其他环节（需求解析→匹配→BOM→报价）正常运行。电磁计算引擎 API 化完成后自动升级 |

#### Elephant 2: 法拉迪核心技术人员离职，项目断档

| 维度 | 内容 |
|------|------|
| **概率** | 低（已签约，团队稳定） |
| **影响** | 致命——知识库回溯教学中断，计算引擎对接无人协调 |
| **Plan B** | ① 项目启动前录制至少 10 个标杆案例的完整视频讲解（含屏幕录制），作为知识库冷启动保底。② 所有 API 接口文档化、代码仓库化，确保任何 Python 开发者可在 2 天内接手 Tool Executor 集成工作。③ 物料价格库设计为独立模块，不强依赖特定人员 |

## 5.2 Red Team 攻击 —— 攻击五大承载假设

---

### 攻击假设 1: "30 分钟出草案"

| 维度 | 内容 |
|------|------|
| **攻击问题** | "30 分钟"是端到端时间还是纯 Agent 处理时间？销售上传文件后去干别的事算不算？对话补全缺失参数要几个来回？如果客户说"我也不知道绝缘等级，你帮我定"，Agent 能自己决策吗？ |
| **为什么重要** | 这是核心价值主张。如果实际体验是"上传→等 5 分钟→收到 3 个问题→等销售回复→再等 10 分钟→又来 2 个问题"，真实体感可能是 2-3 小时（含销售响应间隙），与"30 分钟"严重不符 |
| **最廉价验证** | 用 5 个真实历史项目的需求描述（脱敏），人工模拟整个流程：自己扮演 Agent 执行每一步，严格计时。注意区分"Agent 处理时间"和"含等待的墙钟时间" |
| **Kill Criteria** | 在模拟测试中，如果"Agent 处理时间"（不含销售响应间隙）P50 > 15 分钟，或需要 > 3 轮对话补全才能出草案，则假设不成立。如果需要 > 5 轮对话补全，则"30 分钟"承诺需降级为"2 小时内" |

---

### 攻击假设 2: "50-100 份历史项目即可起步"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 50-100 份是按项目数量算还是按覆盖场景数算？如果 100 份全是同容量段（比如都是 1000kVA 以下），遇到 3000kVA 项目怎么办？历史项目数据格式统一吗？有多少是"有完整计算结果"的，有多少只有"最终报价单"？ |
| **为什么重要** | 数据质量决定系统下限。如果法拉迪 100 份历史数据中只有 30 份有完整电磁计算结果，其余只有 PDF 报价单，那 Agent 的"导入计算数据"能力只能用在 30% 的匹配上 |
| **最廉价验证** | 让法拉迪提供一份历史项目清单（项目编号+容量段+电压等级+是否有完整计算结果），画一个参数覆盖矩阵，检查 Top 10 高频需求场景的覆盖率。如果 < 60%，需要调整冷启动策略 |
| **Kill Criteria** | 历史计算项目中，Top 10 高频参数组合（容量段×电压×冷却方式）覆盖率 < 50%，或"有完整计算结果"的项目 < 30 份 |

---

### 攻击假设 3: "销售会用飞书机器人"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 销售当前最习惯的工具是什么？是飞书、微信、电话、还是 Excel？"发消息给机器人上传文件"这个操作对非技术人员友好吗？如果销售在客户现场用手机，文件上传体验如何？ |
| **为什么重要** | 再好的 Agent，如果销售不用就是零价值。飞书机器人是"销售入口"，它的使用门槛直接决定用户采纳率 |
| **最廉价验证** | 做一个"假机器人"：在飞书群发一个固定消息"请上传客户需求文件"，销售回复文件后，5 分钟内手动发一段"解析结果"（自己编的就行），观察销售是否愿意配合这个流程。如果连"假装的"流程都无人响应，真实版更不可能成功 |
| **Kill Criteria** | 10 名目标销售中，< 3 人在 2 周内主动使用假机器人上传过文件（含演示引导），或使用后明确表示"太麻烦不如打电话" |

---

### 攻击假设 4: "专家每周 2-3 小时回溯教学"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 专家的日常 KPI 是什么？回溯教学是否纳入考核？如果一个专家正在赶一个紧急项目，"2-3 小时回溯历史项目"是优先还是延后？ASR→结构化→确认这个流程，专家觉得"有用"还是"额外负担"？ |
| **为什么重要** | 知识库是 Agent 的"大脑"。如果专家不持续灌入案例，Agent 能力永远停在冷启动水平。这是整个系统的长期竞争力来源 |
| **最廉价验证** | 第 1 周就安排 1 次试录实验，让专家翻 2 个历史项目口述评审逻辑，测试完整流程的摩擦系数。同时与法拉迪管理层沟通，确认是否将"知识库贡献"纳入专家绩效考核 |
| **Kill Criteria** | 试录实验中，专家明确表示"太浪费时间"或"我不确定该说什么"的比例 > 50%，或第 4 周实际累计录入 < 10 个高质量案例 |

---

### 攻击假设 5: "电磁计算引擎 API 足够快"

| 维度 | 内容 |
|------|------|
| **攻击问题** | "足够快"的定义是什么？1 秒？10 秒？10 分钟？当前 `run_calc` 的 P50/P95 延迟是多少？是否支持异步提交+轮询？并发计算能力如何（如果 5 个销售同时下单）？超时阈值设多少？ |
| **为什么重要** | 电磁计算是方案优化的核心环节。如果这一步慢了，其他所有步骤的加速都失去意义——"30 分钟出草案"的承诺直接破产 |
| **最廉价验证** | 在法拉迪测试环境，用 10 个不同复杂度的历史项目跑 `run_calc`，记录端到端耗时（提交→结果可取）。按复杂度分 3 档（简单/中等/复杂），分别记录 P50/P95 |
| **Kill Criteria** | 中等复杂度项目的 `run_calc` P95 > 10 分钟（异步模式下从提交到结果可取），或复杂项目 > 20 分钟 |

## 5.3 用户故事（User Stories）

---

### US-1: 销售 —— 上传需求文件自动解析

**As a** 销售人员, **I want** 在飞书机器人中上传客户发来的需求文件（PDF/Word/Excel），**so that** 系统自动提取技术参数并结构化，我不需要手动转述或翻译客户原始文件。

**验收标准（AC）:**
1. 支持 PDF、Word、Excel、纯文本消息四种输入格式
2. 上传后 ≤ 60 秒返回结构化参数提取结果
3. 提取结果包含：产品类型、容量、电压、冷却方式、特殊要求等关键字段
4. 每个提取字段标注置信度（高/中/低），低置信度字段标黄提示
5. 错误的提取结果可由销售在对话中直接修改

---

### US-2: 销售 —— 对话式补全缺失参数

**As a** 销售人员, **I want** 当需求文件中缺少某些参数时，Agent 以自然语言对话形式问我，**so that** 我无需理解技术术语含义就能补全信息，直接转发客户原话或用大白话回复即可。

**验收标准（AC）:**
1. 识别出缺失参数后 ≤ 30 秒发起追问
2. 追问使用自然语言（非术语），例如："客户有提到安装在室内还是室外吗？"而非"请确认 IP 防护等级"
3. 销售可用自然语言回复，Agent 自动提取填入对应字段（如销售说"室外，下雨的"，Agent 自动填入 IP54）
4. 最多 3 轮对话完成参数补全（超过 3 轮标红提示需专家介入）
5. 补全过程中可随时说"就用默认值"跳过，Agent 自动填充行业默认值并标注

---

### US-3: 销售 —— 查看匹配到的历史方案

**As a** 销售人员, **I want** 看到 Agent 匹配到的最接近的历史项目及其与当前需求的差异对比，**so that** 我能快速判断方案是否靠谱，必要时调整需求或选择不同匹配结果。

**验收标准（AC）:**
1. 返回 Top 3 匹配结果，每个显示匹配度百分比
2. 每个结果以表格形式展示关键参数对比（历史值 vs 当前需求）
3. 差异项高亮标注（容量不同/电压不同/冷却方式不同等）
4. 销售可选择"用这个方案"或"换一个匹配结果"
5. 匹配结果 ≤ 10 秒返回

---

### US-4: 专家 —— 审核 Agent 生成的报价草案

**As a** 技术专家, **I want** 在 Web 控制台看到 Agent 生成的完整报价草案（含需求解析、匹配项目、计算结果、BOM、报价明细），**so that** 我能在 ≤ 10 分钟内确认或驳回，确保报价准确性和技术可行性。

**验收标准（AC）:**
1. 审核页面一次性展示全部信息：需求参数、匹配项目、电磁计算结果、BOM、报价明细
2. 支持逐项审核和批注：专家可在任意字段旁添加批注
3. 一键"通过"或"驳回"，驳回必须填写原因
4. 专家修改的字段自动标注"专家修正"，用于后续 Agent 学习
5. 审核操作耗时 ≤ 10 分钟（通过界面设计保证关键信息一目了然）

---

### US-5: 业务经理 —— 查看报价统计和转化率

**As a** 业务经理, **I want** 看到所有报价的统计仪表盘（报价数量、平均响应时间、通过率、驳回原因分布），**so that** 我能评估系统效果并做出资源调配决策。

**验收标准（AC）:**
1. 仪表盘展示：累计报价数、平均生成时间、平均审核时间、通过率、Top 5 驳回原因
2. 支持按时间范围（日/周/月）筛选
3. 支持按销售/产品类型/客户分组查看
4. 数据实时更新（≤ 5 分钟延迟）
5. 支持导出报表（Excel/PDF）

---

### US-6: 系统管理员 —— 管理物料价格库

**As a** 系统管理员, **I want** 通过 Web 控制台导入/更新物料价格数据（支持 Excel 批量导入），**so that** 报价中的物料成本始终反映最新市场价。

**验收标准（AC）:**
1. 支持 Excel/CSV 批量导入物料价格数据
2. 导入时自动校验：料号重复提醒、价格异常值（偏差 > 50%）标黄
3. 导入后 ≤ 1 分钟内新价格生效
4. 保留历史版本，支持回滚到任意历史价格
5. 支持按料号/类别/供应商查询当前价格

---

### US-7: 专家 —— 回溯教学录入历史案例

**As a** 技术专家, **I want** 翻开一个历史项目，边看边口述评审逻辑和决策理由，系统自动结构化入库，**so that** 我不需要花时间写文档，但我的经验能被 Agent 学习。

**验收标准（AC）:**
1. 支持"选择历史项目→开始录制"的简单操作流程
2. 语音录制 → ASR 转文字 → LLM 结构化为"需求-方案-决策"三元组，全程 ≤ 2 分钟完成一个案例
3. 结构化结果供专家确认/修改后入库
4. 入库时自动打标签（产品类型、场景、难度等级）
5. 一个 30 分钟的录制session可完成 ≥ 10 个案例的录入

---

### US-8: 销售 —— 客户修改需求后自动更新报价

**As a** 销售人员, **I want** 当客户修改需求时（如改容量、改电压），我能告诉 Agent 哪里变了，Agent 自动更新方案和报价，**so that** 我不需要重新走一遍全流程。

**验收标准（AC）:**
1. 销售用自然语言描述变更（如"客户要把容量从 1000 改成 1250"），Agent 自动识别变更项
2. 仅对变更部分重新计算，复用未变更部分的数据
3. 更新后的报价与原报价差异一目了然（哪些变了、变了多少）
4. 更新耗时 ≤ 原生成时间的 30%（因为只重算差异部分）
5. 保留历史版本，可对比查看

---

### US-9: 专家 —— 查看计算结果的置信度和依据

**As a** 技术专家, **I want** 在审核报价时能看到 Agent 方案的置信度评分和决策依据（匹配了哪个历史项目、哪些参数做了调整、调整理由），**so that** 我能高效判断需要重点关注哪些部分，而非从头审核。

**验收标准（AC）:**
1. 每个方案展示综合置信度评分（基于匹配度+参数覆盖度+历史类似方案成功率）
2. 标注每个关键参数的来源：来自哪个历史项目、是否被 Agent 调整、调整理由
3. 低置信度字段（< 60%）自动标红，提示专家重点关注
4. 专家点击任意字段可查看完整的决策链路
5. 支持"一键折叠/展开"，专家可选择只看标红项

---

### US-10: 系统管理员 —— 监控 Agent 运行健康状态

**As a** 系统管理员, **I want** 看到 Agent 各环节（需求解析、方案匹配、计算、BOM、报价）的运行状态和耗时，**so that** 我能及时发现和定位问题。

**验收标准（AC）:**
1. 实时展示每个 Agent 任务的进度和当前阶段
2. 记录每个环节的耗时（P50/P95），自动标红超时任务
3. 记录每个 Tool 的调用成功率和平均响应时间
4. 支持查看 Celery 异步任务队列深度和 Worker 状态
5. 异常事件（计算超时、API 调用失败）自动告警
