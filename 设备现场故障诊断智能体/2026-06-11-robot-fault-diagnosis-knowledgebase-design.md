# 机器人现场故障诊断知识库产品设计

生成日期：2026-06-11

## 1. 产品定位

本产品不是普通文档知识库，而是一套面向机器人现场问题的故障诊断系统。

系统分成两条产品线：

1. 内部研发诊断台
2. 客户在线诊断模块

内部研发诊断台面向技术负责人、核心研发和授权内部人员，可访问绝密设计资料、平台 API 和 MySQL 数据，用于深度定位 Bug、分析设计缺陷、支撑产品改进。

客户在线诊断模块作为现有机器人管理平台的增值模块，可独立交付和售卖。它只能访问客户可见诊断知识和授权范围内的平台数据，不能暴露内部设计资产。

## 2. 第一版用户与重点

第一版优先服务技术负责人。

第一版核心链路：

1. 输入一个现场问题。
2. 识别项目、电站、设备、时间范围和可能故障类型。
3. 通过平台 API 读取当前设备数据。
4. 通过 MySQL 查询历史证据。
5. 检索内部设计资料和内部运维知识。
6. 生成内部技术分析报告。
7. 生成可执行排查步骤。
8. 将分析沉淀为内部案例或故障知识卡。
9. 生成客户版知识草稿，等待人工审核。

第一版优先追求诊断有效性，不优先追求客户前台展示完整度。

## 3. 知识分级

知识分级同时表达权限边界和产品交付边界。

### L0：绝密研发资料

可见范围：

- 技术负责人
- 核心研发
- 明确授权的内部人员

典型内容：

- 源码
- 固件工程
- 硬件原理图
- PCB 文件
- BOM
- 原始设计资料
- 底层协议细节
- 内部缺陷分析
- 未成熟或未发布的设计资料

用途：

- 深度 Bug 定位
- 系统设计改进
- 根因分析
- 生成脱敏知识的源材料

客户可见性：

- 客户不可见

### L1：内部运维知识

可见范围：

- 公司运维人员
- 售后人员
- 技术支持
- 授权内部用户

典型内容：

- 内部故障知识卡
- 详细排查流程
- 内部测试结果
- 设备版本差异
- 已知问题处理经验
- 内部案例分析

用途：

- 内部排查
- 售后支持
- 知识沉淀
- 生成客户版知识草稿

客户可见性：

- 客户不可见

### L2：客户可见诊断知识

可见范围：

- 客户
- 客户运维用户
- 项目方用户

典型内容：

- 客户版故障知识卡
- FAQ
- 标准排查建议
- 设备状态解释
- 脱敏后的测试结论
- 简化后的设计摘要

用途：

- 客户自助排查
- 降低售后沟通成本
- 支撑在线诊断模块

客户可见性：

- 客户可见

### L3：客户可见诊断结果

可见范围：

- 客户
- 客户运维用户
- 项目方用户

典型内容：

- 单次故障诊断报告
- 设备状态摘要
- 建议处理动作
- 需要联系售后的提示

用途：

- 展示某一次在线诊断的结果

客户可见性：

- 客户可见

## 4. 核心安全原则

L0 和 L1 内容不能自动进入客户侧。

任何从内部侧流向客户侧的知识，都必须经过：

```text
提炼 -> 脱敏 -> 权限标注 -> 人工审核 -> 发布
```

客户模块只能使用 L2 知识、L3 报告和客户授权范围内的平台数据。

## 5. 双轨架构

### 5.1 内部研发诊断台

目标：

- 服务技术负责人和内部团队深度诊断。
- 关联现场现象、源码、硬件、BOM、设计文件和平台数据。
- 定位产品 Bug 和设计缺陷。
- 生成 L1 内部故障知识卡。
- 生成 L2 客户版知识草稿。

可访问数据：

- L0 绝密研发资料
- L1 内部运维知识
- 平台 API 只读数据
- API 诊断动作
- MySQL 历史数据

允许的 API 能力：

- 查询设备详情
- 查询在线状态
- 查询最后上报时间
- 查询当前告警
- 查询当前任务
- 查询最近遥测
- 刷新设备状态
- 请求设备自检
- 拉取最新日志
- 拉取最近协议报文

第一版禁止的 API 能力：

- 启动机器人
- 停止机器人
- 修改参数
- 远程重启
- 下发运动控制
- 执行清扫任务
- 修改平台数据

### 5.2 客户在线诊断模块

目标：

- 作为现有机器人管理平台的可售卖增值模块。
- 支持客户自助诊断已知或常见问题。
- 输出安全、可读、可交付的客户诊断报告。

可访问数据：

- L2 客户可见诊断知识
- L3 客户可见诊断结果
- 客户授权范围内的平台设备数据
- 面向客户开放的平台 API
- 按客户权限限制后的 MySQL 数据

禁止访问数据：

- L0 绝密研发资料
- L1 内部运维知识
- 源码
- 硬件原理图
- PCB 文件
- BOM
- 内部缺陷分析
- 内部专用排查细节

## 6. 核心产品模块

### 6.1 故障诊断台

主入口页面。

能力：

- 自然语言输入现场问题。
- 可补充项目、电站、设备、时间范围。
- 可粘贴日志、协议报文、平台数据、测试记录。
- 显示系统识别出的分析上下文。
- 显示本次计划查询的数据。
- 启动诊断分析。

### 6.2 平台 API 接入层

负责当前状态和诊断动作。

能力：

- 设备详情
- 在线状态
- 最后上报时间
- 当前告警
- 当前任务
- 最近遥测
- 状态刷新
- 设备自检
- 日志拉取
- 最近报文拉取

### 6.3 MySQL 只读查询层

AI 不能直接对生产数据库生成任意 SQL。

系统应封装安全查询工具，例如：

- 查询设备基础信息
- 查询最近心跳时间线
- 查询最近遥测时间线
- 查询告警时间线
- 查询任务时间线
- 查询命令时间线
- 查询离线记录
- 查询同电站设备状态对比
- 查询同型号或同版本设备对比
- 查询历史相似故障

### 6.4 内部知识检索

内部研发诊断台可索引 L0 和 L1。

优先处理的内部资料：

- 源码和代码知识图谱
- 硬件原理图
- PCB 文件
- BOM
- 详细设计文件
- 测试结果
- 历史问题文档
- 交付文档
- 协议文档
- 内部分析笔记

检索分三层：

1. 文件元数据索引
2. 高价值文档全文索引
3. 结构化知识抽取，包括故障卡、协议表、版本字典、故障码字典、案例记录

### 6.5 故障知识卡库

故障知识卡让诊断结果稳定、可维护。

每张故障卡包含：

- 故障名称
- 现象关键词
- 适用设备、项目或版本
- 需要查询的平台 API 数据
- 需要查询的 MySQL 历史数据
- 需要检索的知识来源
- 判断规则
- 证据要求
- 排查步骤
- 相关内部案例
- 可见等级：L1 或 L2

第一批故障卡建议：

- 设备离线或不上线
- 485 命令无响应
- 电机不动作
- 主从电机不同步或走偏
- 上限电流过限停机
- 电池低压或供电异常
- 任务未执行或执行中断
- 平台有任务但设备无响应
- 平台数据异常或状态不一致

### 6.6 AI 诊断引擎

AI 输出必须区分：

- 事实：来自 API、MySQL 和文档。
- 推断：基于证据的模型判断。
- 建议：排查或后续处理动作。

已知问题诊断：

- 匹配故障知识卡。
- 查询所需证据。
- 应用判断规则。
- 对可能原因排序。
- 生成排查步骤。

未知问题诊断：

- 构建设备事件时间线。
- 找问题前后的异常变化。
- 对比相似设备、电站、版本和历史案例。
- 检索相关设计知识和运维知识。
- 输出可能相关因素和下一步取证建议。

### 6.7 案例库

每次诊断都可以保存为案例。

案例字段：

- 原始问题
- 识别出的设备、电站、项目和时间范围
- API 摘要
- MySQL 查询摘要
- 检索到的知识
- AI 报告
- 排查步骤
- 最终确认原因
- 处理动作
- 验证结果
- 可见等级

## 7. 诊断流程

```text
用户输入现场问题
  -> 解析项目、电站、设备、时间、故障类型
  -> 匹配故障知识卡
  -> 生成数据查询计划
  -> 调用平台 API
  -> 执行 MySQL 只读查询
  -> 按用户模式检索 L0/L1 或 L2 知识
  -> 整理证据
  -> 生成诊断报告
  -> 生成排查步骤
  -> 保存诊断快照
  -> 创建或更新内部故障卡
  -> 可选生成客户版 L2 草稿
```

## 8. 报告结构

内部报告：

1. 结论摘要
2. 设备与问题上下文
3. 当前 API 状态
4. 历史事件时间线
5. 可能原因排序
6. 证据链
7. 排查步骤
8. 相关设计、代码、硬件、运维资料
9. 缺失信息和下一步动作
10. 建议生成或更新的案例/故障卡

客户报告：

1. 问题摘要
2. 设备状态摘要
3. 可能原因
4. 建议检查项
5. 推荐处理动作
6. 需要联系售后的提示

客户报告不能暴露 L0 或 L1 细节。

## 9. MVP 范围

MVP 是内部研发诊断台，但设计时预留未来客户模块。

MVP 必做能力：

1. 故障诊断台
2. 平台 API 读取和诊断动作
3. MySQL 只读查询工具
4. L0/L1 内部知识检索
5. 内部 AI 诊断报告
6. 排查步骤生成
7. 诊断快照保存
8. L1 内部故障卡草稿生成
9. L2 客户版知识草稿生成，带人工审核状态

MVP 暂不做：

- 客户前台诊断页面
- 客户权限体系
- L2/L3 自动发布
- 控制类 API 动作
- 平台数据修改
- 复杂知识图谱编辑器
- 视频/图片 AI 诊断
- 商业计费
- 完整多租户交付系统

## 10. 版本里程碑

### V0.1：数据和知识接入验证

目标：

- 接通一个测试 MySQL 数据源。
- 接通一组平台 API。
- 扫描本地或内部资料。
- 能检索设备状态、历史记录和知识片段。

### V0.2：内部诊断闭环

目标：

- 输入问题。
- 自动获取平台和 MySQL 数据。
- 检索内部知识。
- 生成内部报告。
- 生成排查步骤。
- 保存诊断快照。

### V0.3：故障卡和案例沉淀

目标：

- 将报告转换为 L1 故障卡草稿。
- 人工确认故障卡。
- 检索相似案例。
- 对已知问题使用故障卡分析。

### V0.4：客户知识草稿

目标：

- 从 L1 故障卡生成 L2 草稿。
- 执行脱敏检查。
- 标记审核状态。
- 为客户侧模块准备知识资产。

### V1.0：客户在线诊断模块

目标：

- 集成到现有机器人管理平台。
- 只使用 L2/L3。
- 读取客户授权的平台数据。
- 生成客户安全报告。
- 打包为可独立售卖的平台模块。

## 11. 第一阶段成功标准

第一阶段成功标准不是“回答所有问题都正确”，而是：

给定一个真实设备问题，系统能自动查询平台数据、查询 MySQL 历史数据、检索内部知识，并生成一份技术负责人愿意拿来做判断的技术分析报告。

第一阶段必须做到：

- 分析有证据。
- 不确定点清楚。
- 下一步取证动作明确。
- 不泄露 L0/L1 到客户侧。
- 不执行任何控制动作。

## 12. 关键风险

### 12.1 数据边界泄露

风险：

- L0 或 L1 内容进入客户可见输出。

缓解：

- 每条知识都带可见等级。
- L2 发布前必须人工审核。
- 内部模式和客户模式使用不同检索范围、提示词和报告模板。

### 12.2 AI 幻觉

风险：

- AI 给出缺少证据但语气很确定的结论。

缓解：

- 报告必须区分事实、推断和建议。
- 每个可能原因必须给出证据。
- 明确列出缺失信息。

### 12.3 数据库安全

风险：

- AI 生成不安全或高成本 SQL。

缓解：

- 只暴露预定义的只读查询工具。
- 使用最小权限数据库账号。
- 记录查询计划和查询结果。

### 12.4 API 安全

风险：

- 诊断动作误影响机器人行为。

缓解：

- MVP 只允许读取和诊断动作。
- 禁止运动、任务、重启、参数类 API。
- 使用明确的 API 白名单。

### 12.5 产品范围失控

风险：

- 系统同时变成通用知识库、客户门户和诊断引擎，导致第一版过重。

缓解：

- MVP 聚焦内部研发诊断台。
- 客户模块作为后续产品线。
- MVP 中客户知识只生成草稿，不自动发布。
