# 知微·大仪智能体 — 产品方案 V2.0

> **产品名称**：知微·大仪智能体  
> **项目名称**：面向大型仪器的多智能体协同管控平台研究与实现  
> **编制日期**：2025年7月  
> **版 本**：V2.0（基于竞品分析调整）

---

## 1. 项目概述

### 1.1 背景

杭州电子科技大学自2019年起承担浙江省大型仪器物联网传感器研发、运维及数据解析工作，已在全省226个高校院所安装近13000台物联网传感器，积累近5年的连续运行数据。团队提出了基于深度学习的科学仪器运行状态识别模型（CNN/Attention-LSTM），已获授权5项发明专利、2项软件著作权，制定1项团体标准。

然而，杭电本校目前尚未形成面向自身管理需求的大仪智能管控工具。**省平台做的是全省宏观监管，Genee系统做的是预约计费流程管理**——两者都不回答以下问题：
- 哪台仪器快要坏了？
- 哪个学院的仪器绩效最差？
- 这台仪器该不该买？

本项目正是为解决这一缺口而设立。

### 1.2 产品定位

**知微·大仪智能体**不是另一个大仪管理系统，而是**在Genee和省平台之上叠加的智能分析层**。

| 误解 | 正解 |
|---|---|
| 知微要替代Genee | ❌ 知微不做预约、计费、用户权限——这些Genee做得很好 |
| 知微是另一个省平台 | ❌ 数据单向从省平台拉取，不上行写入 |
| 知微是一个独立系统 | ✅ **知微是Genee和省平台的增值伴侣** |

> **一句话定位**：
> > 知微不改变你现有的预约和计费流程，它回答的是Genee回答不了的三个问题：**哪台仪器快坏了？哪个学院绩效最差？这台仪器该不该买？**

### 1.3 目标用户

| 用户角色 | 核心诉求 | 使用场景 |
|---|---|---|
| 实验室与设备管理处（校级） | 全校大仪监管、绩效考评、购置审批、健康保试点 | 日常监控、周月报、决策会 |
| 校领导 | 仪器资产运行概览、预算决策依据 | 汇报会、审批 |
| （远期）各学院实验中心 | 本院仪器使用分析、开放共享管理 | Phase 2 开放 |

> ⚠️ **用户在日常预约和使用仪器时仍使用Genee系统，知微是管理决策时的辅助工具，不是替代品。**

### 3.1 知微·看板 Agent — 管理驾驶舱

实验室处每天打开系统看到的"第一屏"，只回答三个问题：

#### 3.1.1 三大核心指标卡

| 指标 | 计算口径 | 阈值预警 |
|---|---|---|
| **闲置率 > 30% 仪器数** | 月使用机时 < 30% 额定机时 | ≥5 台标红 |
| **高风险故障仪器数** | 健康指数 < 60 分的仪器 | ≥3 台标红 |
| **当月使用率环比** | (本月均值 − 上月均值) / 上月均值 | 下降 > 10% 标绿 |

#### 3.1.2 仪器总览视图

以表格 + 热力图方式展示全校大仪核心指标：

| 学院 | 仪器名称 | 当月使用率 | 健康指数 | 闲置天数 | 操作 |
|---|---|---|---|---|---|
| 电子信息学院 | SEM扫描电镜 | 78% | 85 | 3 | 详情 |
| 材料与环境学院 | XRD衍射仪 | 22% 🔴 | 92 | 45 | 详情 |
| 计算机学院 | GPU集群 | 95% | 72 ⚠️ | 0 | 详情 |

- 支持按学院、按仪器类型、按健康状态筛选
- 支持导出 Excel/PDF 报表

#### 3.1.3 趋势图

- 近12个月全校大仪使用率趋势曲线
- 各学院使用率排行饼图/柱状图
- 故障报警次数月度统计

### 3.2 知微·预警 Agent — 智能预警与健康保

这是产品**最核心的技术创新点**，也是竞品（基理科技Genee、久其软件）完全不具备的能力。

#### 3.2.1 健康指数模型

每台仪器每日自动计算 **健康指数（0~100分）**：

| 分值区间 | 状态 | 管理动作 |
|---|---|---|
| 85~100 | 健康 | 正常维护 |
| 70~84 | 关注 | 列入观察，提醒每周检查 |
| 50~69 | 需检修 | 通知管理员安排检修 |
| 0~49 | 危险 | 建议立即停机维修 |

计算因子：
- **历史故障频率**（过去12个月维修记录）
- **实时运行参数偏移**（电流、振动、温度与基线偏差）
- **使用强度**（连续运行时长、负载率）
- **同类仪器横向对比**（校内同型号的健康基线）

#### 3.2.2 故障提前预警

基于 Attention-LSTM 模型，对每台仪器**提前7天**预测故障概率：

- 预警分级：蓝（关注）/ 黄（提醒）/ 红（告警）
- 推送通道：钉钉群机器人（杭电办公平台）
- 预警详情：仪器名称、学院位置、预测故障类型、建议措施

#### 3.2.3 健康保试点对接

- 为每台大仪输出健康评级报告
- 保险公司根据健康指数确定保费折扣
- 支持批量导出保险投保清单

---

### 3.3 知微·决策 Agent — 绩效评价与购置决策

这是实验室处**最有痛点的功能**——每年预算分配和绩效考核。

#### 3.3.1 学院绩效评价

自动计算各学院大仪管理绩效，支持年度/季度考核：

| 评价维度 | 权重 | 计算方式 |
|---|---|---|
| 平均使用率 | 35% | 学院所有大仪月均使用率均值 |
| 开放共享率 | 25% | 对外共享机时 / 总机时 |
| 故障率 | 20% | 年维修次数 / 仪器台数（反向） |
| 产出成果 | 20% | 支撑的论文、专利、项目数量 |

- 学院排名 → 自动生成考核报告
- 与上年度对比 → 进步/退步标注
- **报告的边界**：知微产出分析数据，实验室处可将其导入Genee系统或直接用于汇报

#### 3.3.2 购置决策辅助

系统提供 **购置建议报告**，包含：

1. **校内同类仪器检索**：名称模糊匹配，列出校内同类型/同型号仪器清单
2. **使用率分析**：现有同类仪器的历史平均使用率
3. **饱和度预测**：如果新增一台，全校同类仪器的预期利用率变化
4. **建议结论**：推荐购买 / 不建议购买 / 建议调剂现有仪器

**示例输出**：

```
申购仪器：场发射扫描电镜（SEM）
申购学院：材料与环境学院
预算：380万元

校内同类仪器：3台
  - 电子信息学院 SEM（使用率 78%）
  - 理学院 SEM（使用率 62%）
  - 材环学院 SEM（使用率 22%，闲置中）

分析结论：
  ⚠️ 不建议购置
  理由：材环学院已有1台SEM闲置率78%，建议先评估该台仪器的共享使用方案，
        若利用率仍无法提升，再考虑采购决策。
```

#### 3.3.3 开放策略建议

基于忙闲时段分析模型，为每台仪器推荐最优开放方案：

- "这台仪器周二至周四下午最空闲，建议开放对外共享"
- "该仪器晚间（18:00-22:00）使用率仅5%，可开展夜间共享服务"

### 3.4 知微·数据 Agent — 数据底座

作为底层支撑Agent，统一封装数据接入、模型推理、画像计算。

#### 3.4.1 数据接入

| 数据源 | 内容 | 来源 | 更新频率 |
|---|---|---|---|
| 省平台IoT传感器 | 运行状态、电流、振动、温度等 | 省平台API | 分钟级 |
| 省平台静态库 | 仪器型号、购置日期、学院归属等 | 省平台API | 日级 |
| 维修记录 | 故障时间、维修内容、费用 | 省平台/手工录入 | 事件驱动 |
| 预约使用记录 | 预约/使用机时 | 省平台（源自信电Genee） | 日级 |

> 所有数据来源均为**省平台数据库**，不与Genee系统直接对接，避免集成风险。

#### 3.4.2 大仪画像计算

对每台仪器自动生成多维度画像，每24小时更新一次：

| 画像维度 | 指标示例 |
|---|---|
| 基本属性 | 型号、购置年份、原值、所属学院 |
| 运行画像 | 月均使用率、累计运行时长、忙闲时段分布 |
| 健康画像 | 健康指数、维修次数、故障间隔 |
| 贡献画像 | 支撑论文数、支撑项目数、共享收益 |
| 效益画像 | 使用率效益比、投入产出评分 |

## 5. 生态融合策略

### 5.1 与省平台的融合（数据层）

**现状**：省平台IoT数据库已有杭电所有大仪的5年传感器数据 + 仪器静态信息。知微团队就是省平台的建设运维方。

**融合方式**：定时数据同步任务（每分钟 Pull 增量数据到杭电校内数据库）。

| 数据类 | 同步频率 | 用途 |
|---|---|---|
| 实时运行状态（电流/振动/温度） | 分钟级 | 故障预测 |
| 使用机时记录 | 日级 | 使用率分析 |
| 仪器静态信息（型号/学院/购置年份） | 事件驱动 | 画像基础 |
| 维修记录 | 事件驱动 | 健康指数校准 |

### 5.2 与Genee系统的融合（功能层）

**核心策略**：**不做正面竞争，做增值互补**。

| Genee做 | 知微做 |
|---|---|
| 仪器预约、计费结算 | 健康指数、故障预警 |
| 基础报表（使用机统计） | 绩效自动评价、学院排名 |
| 采购论证流程 | 数据驱动的购置建议报告 |
| 用户管理、权限控制 | 通过省平台获取数据，**不直接对接Genee** |

**融合接口**：
- 知微生成的**绩效评分** → 以Excel/PDF报表形式提供给实验室处
- 知微的**购置建议报告** → 作为Genee采购论证流程的输入附件
- **不修改Genee的一行代码**，所有数据经省平台中转

### 5.3 与钉钉的融合（消息层）

- 预警通知：健康指数异常、高风险故障 → 钉钉群机器人推送
- 日报/周报：每日/每周自动推送关键指标到实验室处群
- 无需额外开发App，钉钉已覆盖杭电全校

### 5.4 与杭电统一认证的融合（身份层）

- 用户登录复用杭电统一身份认证（OAuth/CAS）
- 不做独立用户体系，减少部署阻力

## 7. 风险和应对

| 风险 | 级别 | 应对 |
|---|---|---|
| **数据同步延迟**：省平台不是实时数据库，可能有分钟级延迟 | 🟢 | 分钟级同步已够用（故障预测以小时计） |
| **Genee厂商抵触**：基理科技可能不配合数据对接 | 🟢 | **不需要Genee配合**——知微所有数据来自省平台，不直接对接Genee |
| **实验室处预算不足**：校级项目经费有限 | 🟡 | 2万元启动经费已确认，后续可申请省教育厅项目 |
| **健康保政策未落地**：保险试点尚未明确 | 🟡 | 先做健康指数，政策落地时直接对接 |
| **模型泛化精度**：全省模型在杭电数据上精度可能下降 | 🟡 | 用杭电5年数据微调已有模型 |
