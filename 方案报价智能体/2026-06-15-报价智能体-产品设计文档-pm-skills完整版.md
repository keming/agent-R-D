## 1.1 问题陈述

### 1.1.1 背景：制造业定制化的报价困局

法拉迪（上海）是一家专注变压器制造的企业，其产品属于**多品种小批量定制化**模式——每个客户需求不同，需要从零进行技术评审、方案设计、BOM 拆解、成本核算后才能输出报价。当前从接到客户需求到输出报价，平均需要 **7-15 个工作日**，复杂项目甚至超过 30 天。

客户在采购变压器时通常同时向 **3-5 家供应商询价**，行业经验表明：**先回复方案的一方赢面更大**。报价响应超时导致的丢单率高达 **15-30%**。

### 1.1.2 量化损失

| 损失维度 | 量化估算 | 说明 |
|---------|---------|------|
| **丢单损失** | 15-30% 意向订单因报价超时流失 | 客户同时询价 3-5 家，7-15 天响应已属落后——部分竞品可在 3-5 天内回复 |
| **人力错配** | 技术人员 40-60% 时间花在"出方案/出报价"上 | 资深电磁设计工程师本应做研发创新，却被反复拉去做重复性报价工作 |
| **知识沉没** | 资深工程师离职 = 历史方案和报价经验带走 | 新人上手需 6-12 个月，期间方案质量波动大 |
| **方案不一致** | 同一需求不同工程师报出不同价格 | 老工程师凭经验定价，新工程师查表定价，客户对价格混乱失去信任 |
| **机会成本** | 每个报价占用 2-3 人 × 3-5 天 | 按年薪 20-30 万估算，单次报价隐性成本约 2000-5000 元 |

### 1.1.3 为什么这个问题值得解决

- **直接影响营收**：丢单损失是真金白银的收入流失
- **影响客户关系**：慢响应 = 不专业印象 = 客户流失
- **占用核心资源**：工程师时间被挤占，影响产品研发节奏
- **规模效应**：随着法拉迪业务增长，手工报价流程的瓶颈将越来越严重

## 1.5 验证实验设计

> 遵循 pm-skills `brainstorm-experiments-new` 方法：对 top 3 假设设计低成本验证实验。

### 实验 1：验证 V2——报价速度是否是客户选择供应商的关键因素

| 维度 | 内容 |
|------|------|
| **假设** | 报价响应速度（而非仅价格/质量）是客户选择供应商的关键因素 |
| **实验类型** | **Concierge MVP（门房 MVP）+ 用户访谈** |
| **方法** | 1. 采访法拉迪 3-5 名销售人员："上一次丢单，客户选择竞争对手的原因是什么？"<br>2. 要求法拉迪调取近 12 个月的丢单记录，分析丢单原因分类<br>3. 同时采访 3-5 名法拉迪的下游客户（在允许范围内）："你们选择变压器供应商时，最重要的 3 个因素是什么？响应速度排第几？" |
| **成功标准** | > 60% 的丢单案例中，"响应速度慢"是前三原因之一 |
| **预算** | 500 元（访谈礼品）+ 1 周人力 |
| **Kill Criteria** | 如果丢单主要是因为价格/质量而非速度，需重新评估产品方向 |

### 实验 2：验证 F1——法拉迪是否有足够格式规范的历史计算数据

| 维度 | 内容 |
|------|------|
| **假设** | 法拉迪有 50-100 份格式规范的已完成电磁计算项目数据 |
| **实验类型** | **数据审计（Data Audit）** |
| **方法** | 1. 请求法拉迪提供已完成计算项目的样本（10 份即可）<br>2. 审计每份样本包含的信息完整度：<br>　- 输入参数是否完整？<br>　- 电磁计算结果是否可读取？<br>　- BOM 是否关联？<br>　- 最终报价是否记录？<br>3. 统计总量、格式一致性、数据缺失率 |
| **成功标准** | ≥ 50 份项目数据，其中 ≥ 70% 包含完整的输入参数 + 计算结果 + BOM |
| **预算** | 0 元（数据审计）+ 2 天人力 |
| **Kill Criteria** | 如果可用数据 < 30 份或格式严重不一致，需先做数据清洗或调整 Phase 1 方案为"降级模式"（仅基于 PDF 报价单而非计算数据） |

### 实验 3：验证 U1——非技术人员能否通过对话准确表达技术需求

| 维度 | 内容 |
|------|------|
| **假设** | 非技术人员（销售）能够通过对话式交互准确表达变压器技术需求 |
| **实验类型** | **Pretotype（假装有型原型）** |
| **方法** | 1. 搭建一个简单的对话界面（飞书机器人或 Web 聊天窗口）<br>2. 内部准备 3 个真实客户需求场景（从法拉迪历史订单中选取）<br>3. 邀请 3 名法拉迪销售人员，模拟"收到客户需求文件"后，通过对话界面输入需求<br>4. 记录：销售能多快理解提问意图？是否需要技术人员在旁指导？最终参数准确率如何？ |
| **成功标准** | 3 名销售中 ≥ 2 名能在 10 分钟内独立完成需求输入，参数准确率 ≥ 80% |
| **预算** | 1 周开发时间（搭对话界面）+ 0.5 天用户测试 |
| **Kill Criteria** | 如果销售普遍无法理解技术参数提问，需重新设计交互方式（例如改为选项式而非开放式对话） |

### 实验 4（附加）：验证 G1——销售团队是否愿意使用 AI 工具

| 维度 | 内容 |
|------|------|
| **假设** | 法拉迪内部销售团队愿意使用 AI 工具替代传统报价流程 |
| **实验类型** | **Landing Page + 内部 Demo** |
| **方法** | 1. 制作一个 3 分钟的产品演示视频（用虚构但真实感的场景）<br>2. 在法拉迪内部做一次 30 分钟的产品演示会<br>3. 演示后发放简短问卷："你愿意试用吗？最担心什么？"<br>4. 记录意愿度和主要顾虑 |
| **成功标准** | ≥ 70% 的销售人员表示"愿意试用" |
| **预算** | 1 天制作演示视频 + 1 小时演示会 |
| **Kill Criteria** | 如果抵触情绪严重（> 50% 明确拒绝），需优先解决信任问题（如先做"辅助"而非"替代"定位） |

## 2.2 Job Stories

> 遵循 pm-skills `job-stories` 方法：将用户痛点转化为具体的 Job Stories。

### Job Story 1：销售快速响应客户需求

> **When** 我收到客户发来的变压器定制需求文件（PDF/Word/微信消息），  
> **I want** 上传文件后系统自动识别技术参数，并以对话方式帮我补全缺失信息，  
> **so that** 我能在 10 分钟内拿到报价草案，快速回复客户，不被竞品抢走订单。

### Job Story 2：非技术人员理解技术对话

> **When** Agent 追问我一个不懂的技术参数（比如"绝缘等级是 F 级还是 H 级？"），  
> **I want** Agent 用大白话解释这个参数的含义和影响，并提供几个选项供我选择，  
> **so that** 我不需要叫工程师过来帮忙，也能独立完成需求收集。

### Job Story 3：工程师审核 AI 生成的方案

> **When** Agent 生成了一份报价方案草案，  
> **I want** 能清晰看到方案基于哪个历史项目、做了哪些修改、每个数字的来源，  
> **so that** 我可以快速审核确认或指出需要修改的地方，而不是从头重算。

### Job Story 4：销售查看报价进度

> **When** 我提交了报价请求后，  
> **I want** 实时看到当前处理进度（需求解析 → 方案匹配 → 参数优化 → 报价生成），  
> **so that** 我能告诉客户大概什么时候能拿到结果，而不是反复打电话催。

### Job Story 5：商务经理分析成交率

> **When** 月底我需要回顾本月报价情况时，  
> **I want** 看到一个仪表盘，包含本月报价数量、成交率、平均响应时间、各产品线报价分布，  
> **so that** 我能识别哪些环节需要改进，制定下月的价格策略。

### Job Story 6：新人快速上手报价

> **When** 我是刚入职的销售新人，第一次面对客户的变压器定制需求时，  
> **I want** Agent 帮我一步步引导完成需求收集和报价，  
> **so that** 我不需要等师傅带半年就能独立处理报价工作。

### Job Story 7：多轮需求变更

> **When** 客户在看到第一版报价后修改了需求（比如从 AN 冷却改为 AF 冷却），  
> **I want** Agent 自动识别变更点并更新方案和报价，而不是重新走一遍全流程，  
> **so that** 我能快速响应客户的迭代需求，体现专业性。

## 2.3 竞品分析

> 遵循 pm-skills `competitor-analysis` 方法：找 5 个直接竞品/替代方案，做优劣势分析。

### 竞品概览

| # | 竞品/替代方案 | 类型 | 适用场景 |
|---|-------------|------|---------|
| 1 | **传统 Excel 手工报价** | 手动流程 | 法拉迪当前方式 |
| 2 | **CPQ 工具（如 Salesforce CPQ、Conga）** | 商业软件 | 通用制造业配置报价 |
| 3 | **变压器行业 CAD/CAE 集成报价** | 行业工具 | 如 ETAP、Mentor Graphics |
| 4 | **国内 AI 报价工具（如智齿 AI、网易七鱼）** | AI SaaS | 客服/通用报价场景 |
| 5 | **其他变压器厂商的内部系统** | 内部方案 | 大型变压器企业的自建系统 |

### 详细对比分析

#### 1. 传统 Excel 手工报价（法拉迪当前方式）

| 维度 | 评价 |
|------|------|
| **优势** | 无学习成本；灵活度高；完全可控 |
| **劣势** | 效率极低（7-15 天）；知识不沉淀；一致性差；容易出错 |
| **市场份额** | 行业主流（> 80% 的中型企业） |
| **对我们的启示** | 这是我们要替代的目标，而非竞争对手——但要确保切换成本足够低 |

#### 2. CPQ 工具（Salesforce CPQ / Conga）

| 维度 | 评价 |
|------|------|
| **优势** | 成熟的产品配置和定价逻辑；与 CRM 集成；支持审批流 |
| **劣势** | 不理解变压器技术参数（通用工具）；需要大量配置和定制；价格高（年费 10-50 万）；无法做电磁优化计算 |
| **市场份额** | 在非制造行业（SaaS、通信）份额高，在变压器行业几乎为零 |
| **对我们的启示** | **差异化机会**——垂直行业深度 vs 通用工具广度。我们不只是配置产品，而是理解技术参数并自动计算 |

#### 3. 变压器行业 CAD/CAE 集成报价（ETAP 等）

| 维度 | 评价 |
|------|------|
| **优势** | 理解变压器技术参数；可做电磁计算和仿真 |
| **劣势** | 侧重设计环节而非报价流程；操作复杂需专业培训；不支持对话式交互；价格高 |
| **市场份额** | 在大型变压器企业中有使用，中型企业采用率低 |
| **对我们的启示** | **互补关系**——我们的 Agent 可以调用 CAE 工具的计算能力，但前端体验和报价流程是我们独有 |

#### 4. 国内 AI 报价工具（智齿 AI 等）

| 维度 | 评价 |
|------|------|
| **优势** | AI 对话能力强；部署简单；价格亲民 |
| **劣势** | 不理解制造业技术参数；无法做电磁计算；报价逻辑基于通用模板而非行业知识 |
| **市场份额** | 在客服、电商领域有份额，在制造业报价领域几乎为零 |
| **对我们的启示** | **技术路线参考**——它们的对话交互设计值得借鉴，但技术深度远不够 |

#### 5. 其他变压器厂商的内部系统

| 维度 | 评价 |
|------|------|
| **优势** | 高度定制化，贴合企业自身流程 |
| **劣势** | 开发成本高；依赖内部 IT 团队维护；不易复制 |
| **市场份额** | 仅大型企业（如特变电工、保变电气）有能力建设 |
| **对我们的启示** | **市场定位**——我们服务的是无力自建系统的中小型变压器企业，法拉迪就是典型代表 |

### 差异化机会矩阵

| 差异化维度 | 我们的优势 | 竞品劣势 |
|-----------|-----------|---------|
| **行业深度** | 垂直在变压器领域，理解电磁参数 | 通用工具不懂行业 |
| **计算能力** | 直接调用电磁计算引擎，方案基于真实工程数据 | 仅做模板填充，不做技术计算 |
| **交互方式** | 对话式，非技术人员可用 | 多为表单式，需要技术背景 |
| **数据复用** | 自动匹配已完成计算的历史项目 | 每次从零开始 |
| **成本** | 基于已有平台扩展，边际成本低 | CPQ 年费高，自建系统投资大 |

## 2.4 用户旅程地图

> 遵循 pm-skills `customer-journey-map` 方法：从"客户询价收到"到"报价交付"的完整旅程。

### 旅程概览

```
客户询价 → 需求接收 → 需求分析 → 方案设计 → 报价编制 → 内部审批 → 报价交付 → 客户反馈
```

### 详细旅程地图

| 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
|:----:|------|---------|:----:|------|------|
| **① 客户询价** | 微信/邮件/电话/展会 | 销售收到客户需求描述（可能是一段话、一份图纸、一个规格书） | 😊 期待（有商机） | 客户描述不清，信息碎片化 | Agent 自动从多渠道收集需求 |
| **② 需求接收** | 内部邮件/飞书消息 | 销售转发给技术部门，附上客户原始文件 | 😐 中性 | 不确定技术部门什么时候能处理；不知道还需要补充什么信息 | Agent 即时响应，自动解析文件 |
| **③ 需求分析** | 工程师邮件回复/电话 | 工程师审查需求，向销售追问缺失参数 | 😫 焦虑（来回沟通） | 追问 3-5 轮，每轮 1-2 天；销售不懂技术参数含义 | Agent 对话式补全，用大白话提问 |
| **④ 方案设计** | 工程师桌面（本地软件） | 工程师手动查找历史项目，复制参数，重新计算 | 😫 疲惫（重复劳动） | 70% 的项目是相似的，但每次从头算；找不到以前的计算数据 | Agent 自动匹配历史项目并导入数据 |
| **⑤ 报价编制** | Excel/Word | 工程师拆 BOM、算成本、填报价模板 | 😐 中性 | 格式不统一；容易算错；不同工程师报不同价 | Agent 自动拆 BOM、核算成本、生成标准报价 |
| **⑥ 内部审批** | 邮件/线下签字 | 报价单发给技术负责人 → 商务负责人 → 总经理 | 😫 焦虑（等待审批） | 审批人出差/开会，拖 1-3 天；驳回后重新修改再提交 | Agent 内置审批流，手机端一键审批 |
| **⑦ 报价交付** | 邮件/飞书 | 销售把报价单发给客户 | 😊 如释重负 | 格式不专业；附件不全；忘记标注有效期 | Agent 生成标准化专业报价单 |
| **⑧ 客户反馈** | 电话/微信 | 客户反馈意见（价格高/方案不合理/需要修改） | 😫 沮丧（可能丢单） | 不知道丢单原因；修改需求后又要走一遍全流程 | Agent 分析丢单原因，支持快速迭代修改 |

```
     ①询价  ②接收  ③分析  ④设计  ⑤报价  ⑥审批  ⑦交付  ⑧反馈
```

**关键观察**：情绪低谷集中在 ③需求分析（来回追问）和 ④方案设计（重复劳动）——这正是 Agent 要重点解决的环节。

### Agent 干预后的旅程优化

| 阶段 | 传统方式 | Agent 方式 | 情绪改善 |
|:----:|---------|-----------|:--------:|
| ①-③ 需求阶段 | 3-5 天（来回沟通） | 5-10 分钟（对话式补全） | 😫 → 😊 |
| ④ 方案设计 | 2-5 天（从头计算） | 5-10 分钟（历史项目导入+差异优化） | 😫 → 😊 |
| ⑤ 报价编制 | 1-2 天（手动拆 BOM） | 2-3 分钟（自动拆解） | 😐 → 😊 |
| ⑥ 内部审批 | 1-3 天（线下流转） | 实时（飞书审批卡片） | 😫 → 😊 |
| **总计** | **7-15 天** | **15-30 分钟** | |

### 机会 1：缩短报价响应时间

**目标**：将报价响应时间从 7-15 天压缩到 30 分钟 - 2 小时

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 1a | **对话式需求解析**——LLM 从客户文件中自动提取参数，对话式补全缺失信息 | 先用 10 个真实需求文件测试 LLM 提取准确率 | 响应时间缩短 80%（3-5 天 → 5-10 分钟） |
| 1b | **已完成项目自动匹配**——需求参数匹配历史项目库，导入计算数据 | 用 20 个历史项目测试匹配算法的准确率 | 方案设计时间缩短 90%（2-5 天 → 5-10 分钟） |
| 1c | **异步计算 + 实时交互**——电磁计算走后台，销售端实时看进度 | 对比同步/异步两种模式的用户体验 | 用户等待焦虑降低 60% |

### 机会 2：提高方案质量与一致性

**目标**：不同销售/工程师给出的方案质量一致，丢单率降低

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 2a | **标准化报价模板**——统一报价单格式、技术方案格式、附件要求 | 让 3 名工程师各出一份报价，对比标准化前后的差异 | 方案一致性从 60% → 95% |
| 2b | **知识沉淀与复用**——每个成交/丢单项目自动入库，标注决策理由 | 用 3 个月积累 50 个全链路案例，测试检索准确率 | 新人上手时间从 6-12 个月 → 2-4 个月 |
| 2c | **专家审核 + 反馈闭环**——HITL 审核的每个修改都记录为训练数据 | 设计审核界面原型，测试专家操作效率 | 报价准确率随使用持续提升 |

### 机会 3：降低人力成本

**目标**：技术人员从 40-60% 报价工作中释放，回归研发

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 3a | **Agent 自动处理 80% 标准项目**——非标/复杂项目才需要工程师介入 | 定义"标准项目"标准（参数范围、复杂度评分），测试自动处理率 | 工程师报价工时降低 60% |
| 3b | **销售自助报价**——简单项目销售可直接出报价单，无需工程师参与 | 模拟 5 个简单场景让销售独立操作 Agent，测试成功率 | 简单项目工程师参与率从 100% → 0% |
| 3c | **新人加速**——Agent 辅助下新人可快速独立，减少老人带新人的时间 | 设计新人 onboarding 流程，对比传统 vs Agent 辅助的学习曲线 | 新人独立时间从 6 个月 → 2 个月 |

### 机会 4：提升客户体验

**目标**：客户对报价过程的满意度提升，复购率增加

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 4a | **报价进度可视化**——客户可通过链接查看报价处理进度 | 设计进度查询页面原型，测试客户使用意愿 | 客户催单电话减少 50% |
| 4b | **多轮修改快速响应**——客户修改需求后 Agent 自动更新方案和报价 | 用 3 个模拟场景测试需求变更后的更新速度 | 修改响应时间从 3-5 天 → 10 分钟 |
| 4c | **专业附件包**——报价单附带技术方案书、三维预览图、BOM 简表 | 测试附件包对客户决策的影响 | 报价专业度评分提升 |

### 机会 5：数据驱动的价格策略

**目标**：基于历史数据优化定价，提升利润率

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 5a | **报价看板**——实时展示报价数量、成交率、响应时间、利润分布 | 搭建一个简单的数据看板原型，测试王总的使用频率 | 价格决策从"拍脑袋" → 数据驱动 |
| 5b | **智能定价建议**——基于历史成交数据，Agent 建议合理报价范围 | 用 30 个历史成交数据分析价格与成交率的关系 | 成交率提升 10-15% |
| 5c | **丢单分析**——自动分析丢单原因（价格高/方案差/响应慢） | 收集 20 个丢单案例，人工标注原因 vs Agent 预测原因对比 | 丢单原因识别准确率 ≥ 70% |

### 机会 6：行业知识资产化

**目标**：将法拉迪的报价经验沉淀为可复制的企业资产

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 6a | **专家回溯教学**——资深工程师口述历史项目决策逻辑，Agent 结构化入库 | 每周 2 小时，持续 8 周，积累 150-200 案例 | 知识库冷启动完成 |
| 6b | **决策图谱**——每个报价决策关联"为什么选这个方案"的注释 | 设计知识录入界面原型，测试专家录入效率 | 知识可检索、可解释 |
| 6c | **跨项目学习**——Agent 从成交/丢单数据中学习定价策略 | 需要 500+ 全链路案例后启动 | 智能定价能力 |

### 机会 7：多产品线扩展

**目标**：从干式变压器扩展到油浸式、箱变等产品线

| # | 方案 | 实验建议 | 预期效果 |
|---|------|---------|---------|
| 7a | **参数 Schema 可扩展**——新产品的技术参数可配置化录入 | 设计油浸式变压器的参数 Schema，测试扩展性 | 产品线扩展周期从 3 个月 → 2 周 |
| 7b | **通用报价流程复用**——需求解析→匹配→优化→报价的流程框架可复用 | 用油浸式变压器的 5 个需求测试通用流程 | 新产品线可快速上线 |

### 3.1 价值主张画布（Value Proposition Canvas）

| 维度 | 内容 |
|------|------|
| **Who（目标用户）** | 变压器制造企业的**销售/商务人员**（一线用户）和技术负责人（审核用户）。销售直接面对客户，需要快速响应询价；技术负责人负责方案把关和最终审批 |
| **Why（核心痛点）** | ① 报价响应慢（7-15天），客户同时询价 3-5 家，丢单率 15-30%；② 销售不懂技术参数，依赖技术部门"翻译"客户需求；③ 技术人员 40-60% 时间消耗在重复性报价工作上；④ 历史方案复用靠人脑记忆，经常找不到或找不准；⑤ 新人上手需 6-12 个月，知识随人员流失 |
| **What Before（现有替代方案）** | ① Excel 手工填报价单 + 人工核算成本；② 邮件/电话反复沟通技术部确认方案；③ 翻历史文件夹找类似项目参考；④ 技术人员手动重新计算电磁参数；⑤ 审批流程走纸质或 OA 系统——每一步都耗时且依赖人 |
| **How（我们的解决方案）** | AI 驱动的报价/方案智能体：销售上传客户需求文件 → Agent 自动解析参数、匹配已完成计算的历史项目并导入数据 → 调用电磁计算引擎优化方案 → 自动拆解 BOM、核算成本 → 生成报价单 → 专家审核确认。**全程 15-30 分钟，替代 7-15 天** |
| **What After（使用后状态）** | ① 销售独立完成报价，不依赖技术部"翻译"；② 响应时间从 7-15 天缩短到 30 分钟，抢在竞争对手前面；③ 技术人员从重复报价中解放，回归研发；④ 历史方案数据自动复用，不再"找文件"；⑤ 报价一致性 100%，消除"不同人报不同价"；⑥ 新人上手周期从 6-12 个月缩短到 2-4 周 |
| **Alternatives（竞品对比）** | ① **通用 CPQ 软件**（Salesforce CPQ、配置器）：只做配置和定价，不做电磁计算优化——变压器是技术密集型产品，通用工具无法处理工程计算；② **ERP 内嵌报价模块**：只能基于现有 BOM 和固定公式报价，无法处理"从零设计"的客制化场景；③ **其他变压器厂家的内部系统**：无标准化产品，各厂自研；④ **轨物方案的差异化**：直接对接电磁计算引擎+已完成计算项目库，是唯一能覆盖"需求解析→工程计算→报价输出"全链路的方案 |

### 3.2 产品战略画布（Product Strategy — 9 部分）

#### 1. Vision（愿景）

> **让每一份变压器报价都基于工程验证，让销售 30 分钟内给出客户专业方案——从"报价靠经验"到"报价靠数据"。**

#### 2. Target Segments（客户分群）

| 分群 | 特征 | 痛点强度 | 优先级 |
|------|------|:--------:|:------:|
| **Tier 1：中小型变压器制造企业** | 年产值 5000万-5亿，5-30 人技术团队，多品种小批量定制化为主 | ★★★★★ | **P0** |
| **Tier 2：大型变压器集团** | 年产值 5亿+，有 ERP/PLM 系统，但报价流程仍依赖人工 | ★★★★ | P1（Phase 2+） |
| **Tier 3：电力装备集成商** | 自身不做变压器设计，但需要快速向终端客户报价（贸易型） | ★★★ | P2（Phase 3+） |

**首批目标客户**：法拉迪（已签约，P0 验证客户）→ 同行业同规模企业横向复制。

#### 3. Costs（成本结构）

| 成本项 | Phase 1（1-2月） | Phase 2（3-6月） | Phase 3（6-12月） |
|--------|:-----------------:|:-----------------:|:-----------------:|
| **研发人力** | 2 全职 + 法拉迪技术配合 | 2-3 全职 + 法拉迪配合 | 2 全职维护 + 自动化 |
| **LLM API 调用** | ~¥2000/月 | ~¥5000/月 | ~¥8000/月 |
| **向量数据库/存储** | ~¥500/月 | ~¥1500/月 | ~¥3000/月 |
| **部署/运维** | 复用法拉迪基础设施 | 独立部署 | 扩展部署 |
| **客户成功** | 轨物创始人亲自对接 | 1 名客户成功 | 标准化 onboarding |

**Phase 1 目标成本**：约 ¥15-20 万（人力 + API + 基础设施）。

#### 4. Value Props（核心价值）

| 价值维度 | 对销售的价值 | 对技术负责人的价值 | 对企业决策者的价值 |
|---------|------------|------------------|------------------|
| **速度** | 30 分钟出报价，抢在竞争对手前面 | 从重复报价中解放 | 报价响应快 → 丢单率降低 |
| **质量** | 报价基于工程验证数据，不会"报错" | 方案一致性 100%，风险可控 | 亏本接单概率降低 |
| **知识** | 不懂技术也能出专业报价 | 历史方案自动复用 | 知识不再随人员流失 |
| **成长** | 新人 2-4 周独立出报价 | 专家时间聚焦高价值研发 | 团队能力提升 |

#### 5. Trade-offs（取舍决策）

| 决策项 | 选择 | 放弃 | 理由 |
|--------|------|------|------|
| **覆盖面 vs 深度** | 先深后广——先做干式变压器，验证后再扩展油浸式 | Phase 1 不做油浸式全品类 | 干式变压器占法拉迪营收主体，集中火力验证 |
| **自动化 vs 准确性** | Phase 1 强制 HITL（所有报价人工确认） | 不做全自动报价 | 报价错误成本极高，必须先积累信任 |
| **标准化 vs 灵活性** | 标准化报价模板 + 少量可配置项 | 不做完全自由排版 | 80% 的报价用标准模板足够，20% 极端定制仍人工 |
| **自有平台 vs 依赖法拉迪** | 基于法拉迪 Agent 平台扩展 | 不自建独立平台 | 复用已有资产节省 60-70% 工程量 |
| **定价 vs 免费** | 项目制交付 + 年度订阅 | 不做免费试用 | B2B 制造业，免费试用反而降低信任 |

#### 6. Metrics（成功指标）

| 指标 | Phase 1 目标 | Phase 2 目标 | Phase 3 目标 |
|------|:-----------:|:-----------:|:-----------:|
| **报价响应时间** | ≤ 30 分钟 | ≤ 15 分钟 | ≤ 10 分钟 |
| **HITL 修改率** | < 30%（允许） | < 15% | < 10%（试点自动通过） |
| **报价→成交转化率** | 基线测量 | 提升 10% | 提升 20% |
| **销售独立出报价率** | > 60% | > 80% | > 90% |
| **技术人员报价时间占比** | 降低 30% | 降低 50% | 降低 70% |

#### 7. Growth Strategy（增长策略）

| 阶段 | 策略 | 动作 |
|------|------|------|
| **Phase 1（验证）** | 单客户深耕 | 法拉迪内部 3-5 名销售试用，收集反馈 |
| **Phase 2（复制）** | 同行业横向复制 | 法拉迪成功案例 → 3-5 家同规模变压器厂 |
| **Phase 3（扩展）** | 品类/行业扩展 | 干式→油浸式；变压器→其他电力装备（开关柜、配电柜） |
| **Phase 4（平台化）** | 报价 Agent as a Service | 标准化交付流程，支持新客户 2 周内上线 |

#### 8. Capabilities（核心能力）

| 能力 | 来源 | 可复制性 |
|------|------|:--------:|
| **电磁计算引擎集成** | 法拉迪已有资产 | 需适配各厂商引擎 |
| **已完成计算项目库匹配** | 新建（Phase 1） | 高——每个客户都有历史项目 |
| **LLM 需求理解 + 对话补全** | 通用 AI 能力 | 高——跨行业通用 |
| **变压器领域知识图谱** | 专家回溯教学 | 中——需逐行业积累 |
| **报价全链路自动化** | 新建（Phase 1） | 中——需适配各厂商流程 |

#### 9. Defensibility（护城河）

| 护城河类型 | 具体体现 | 壁垒高度 |
|-----------|---------|:--------:|
| **数据壁垒** | 每个客户使用后积累的"需求-方案-计算-报价-成交"全链路案例库——越用越准，后来者无法复制 | ★★★★★ |
| **知识壁垒** | 专家回溯教学积累的"为什么"决策知识——隐性知识显性化后形成独特资产 | ★★★★ |
| **集成壁垒** | 与电磁计算引擎/BOM引擎/ERP深度集成——切换成本极高 | ★★★★ |
| **网络效应** | 更多客户使用 → 更多案例数据 → 方案匹配更准 → 吸引更多客户 | ★★★ |
| **时间壁垒** | 先发者积累的案例库和领域知识，后来者需要 12-18 个月才能追平 | ★★★★ |

### 3.4 定价策略

#### 3.4.1 报价智能体本身的定价（卖给法拉迪的商业模式）

本产品是 **B2B SaaS + 专业服务**混合模式，向法拉迪（及后续变压器制造企业）收费。

#### 3.4.2 定价模型选择

| 模型 | 优势 | 劣势 | 适用阶段 |
|------|------|------|---------|
| **项目制交付** | 收入确定、客户决策简单 | 不利于持续收入 | Phase 1-2 |
| **年度订阅制** | 持续收入、客户粘性 | 需要产品足够成熟 | Phase 2+ |
| **按量计费** | 与使用量挂钩、公平 | 收入波动、客户难预测 | 不推荐（B2B不适合） |

**推荐策略**：Phase 1-2 采用 **项目制 + 年度维护费**，Phase 3 转向 **年度订阅制**。

#### 3.4.3 价格锚点和参考

| 定价维度 | 参考基准 | 建议定价 |
|---------|---------|---------|
| **项目制交付** | 法拉迪当前合同 Phase 1-3 已覆盖基础平台 | 报价 Agent 扩展包：**¥30-50万**（Phase 1-2 交付） |
| **年度订阅费** | 1 名技术人员年薪 ¥15-25万，报价 Agent 替代 0.5-1 人工作量 | **¥8-15万/年**（含升级维护、知识库更新） |
| **按用户数** | 不推荐单独按用户收费——变压器厂报价人员通常 3-10 人 | 包含在年度订阅中，不限用户数 |
| **增值服务** | 深度定制（油浸式适配、新行业扩展） | **¥5-10万/次** |

#### 3.4.4 定价逻辑

```
客户 ROI 计算：
  当前成本：1 名技术人员 × 50% 时间 × ¥20万/年 = ¥10万/年 纯报价成本
  + 丢单损失：年询价 200 单 × 15% 丢单率 × 平均单价 ¥10万 = ¥300万/年
  
  Agent 成本：¥10万/年（订阅费）
  Agent 价值：
    - 节省技术人员时间：¥5-10万/年
    - 降低丢单率：15% → 5%（保守估计），减少 ¥200万/年 损失
    
  ROI = (¥200万+¥5万) / ¥10万 = 20:1
```

#### 3.4.5 法拉迪特殊定价（首批客户）

| 项目 | 说明 |
|------|------|
| **首年定价** | 项目制交付 ¥30万（含 Phase 1-2 全部功能 + 部署 + 培训） |
| **年度维护** | ¥8万/年（Phase 3 功能 + 知识库更新 + 技术支持） |

| **后续扩展** | 油浸式适配 + 新功能按 ¥5-10万/次 计费 |

### 4.1 北极星指标（North Star Metric）

#### 4.1.1 商业游戏类型判定

| 游戏类型 | 定义 | 匹配度 |
|---------|------|:------:|
| **Attention Game** | 用户注意力/使用时长 | ❌ 不匹配 |
| **Transaction Game** | 交易量/交易额 | ⚠️ 部分匹配 |
| **Productivity Game** | 帮用户完成任务的效率 | ✅ **最佳匹配** |

**判定结果**：报价智能体是典型的 **Productivity Game**——核心价值是帮销售/技术人员更快、更准地完成报价任务。

#### 4.1.2 北极星指标

> **每周完成的报价单数量**（Weekly Completed Quotations）

定义：每周通过报价 Agent 生成并经专家审核通过的报价单数量。

选择理由：
- 直接反映产品核心价值（帮用户完成报价任务）
- 与商业收入强相关（报价越多 → 成交机会越多 → 订阅续费理由越强）
- 可衡量、可追踪、不可作弊

#### 4.1.3 输入指标（Input Metrics）

| 输入指标 | 定义 | 目标 |
|---------|------|------|
| **报价响应时间** | 从上传需求到生成报价单草案的时间 | ≤ 30 分钟（Phase 1）→ ≤ 15 分钟（Phase 2） |
| **HITL 修改率** | 专家审核时需要修改的比例 | < 30%（Phase 1）→ < 10%（Phase 3） |
| **历史项目匹配成功率** | Agent 匹配到可用已完成计算项目的比例 | > 70%（Phase 1）→ > 90%（Phase 2） |
| **销售独立完成率** | 销售无需技术部协助独立出报价的比例 | > 60%（Phase 1）→ > 90%（Phase 3） |
| **报价→成交转化率** | 报价后最终成交的比例 | 基线测量 → 提升 20% |

## 5.1 Pre-Mortem —— 想象失败，反向推导

> **场景设定**：现在是 Phase 1 MVP 上线后第 14 天。产品**已经失败了**。请反向推导原因。

---

### 🐅 Tigers（高概率 × 高影响）—— 这些是我们最该担心的

#### Tiger 1: 历史项目数据质量差，方案匹配命中率低

| 维度 | 内容 |
|------|------|
| **根因链** | 法拉迪历史计算项目缺少结构化元数据（标签/分类/场景） → `search_calculated_projects` 检索依赖的向量检索语义理解弱 → 匹配到"看起来像但其实不相关"的项目 → 导入的数据偏差大 → 专家看到方案后直接驳回 → 销售觉得系统不靠谱放弃使用 |
| **Kill Criteria** | 前 20 次方案匹配中，专家审核通过率 < 50%，或专家平均修改时间 > 15 分钟（说明匹配到的项目偏差太大，还不如从零做） |
| **最廉价验证测试** | 拿 10 个真实历史项目需求作为测试用例，跑 `search_calculated_projects`，让 1-2 名专家盲评匹配结果的相关性打分（1-5 分），如果平均分 < 3.0 则此项假设失败 |

#### Tiger 2: 专家拒绝投入时间做回溯教学

| 维度 | 内容 |
|------|------|
| **根因链** | 专家日常工作忙碌 → "每周 2-3 小时回溯教学"听起来不多但实际被会议/紧急任务挤掉 → 知识库停留在冷启动的 50-100 份 → 覆盖场景有限 → Agent 遇到稍偏的场景就"不会" → 系统能力停滞不前 |
| **Kill Criteria** | 第 4 周结束时，专家实际累计投入 < 8 小时（目标 16-24 小时），或知识库新入库案例 < 20 条 |
| **最廉价验证测试** | 项目启动前先做 1 次 30 分钟的试录实验：找一个典型项目，让专家边翻项目边口述评审逻辑，录音→ASR→结构化→专家确认，测试整个录入流程的摩擦系数。如果专家明确表示"太麻烦"或 30 分钟内无法完成 1 个案例的录入，假设失败 |

#### Tiger 3: 电磁计算引擎 API 响应太慢，30 分钟出草案成空话

| 维度 | 内容 |
|------|------|
| **根因链** | `run_calc` 电磁优化计算单次耗时超预期（复杂方案可能 10-20 分钟） → 加上需求解析(3min)+匹配(5min)+BOM(5min)+报价(2min) → 总耗时 > 30 分钟 → 销售体感"没什么提升" → 与"传统 7-15 天"相比优势不够显著 → 无法形成使用习惯 |
| **Kill Criteria** | 在 Phase 1 测试环境中，对 5 个不同复杂度的典型需求跑端到端流程，P95 总耗时 > 60 分钟 |
| **最廉价验证测试** | 在法拉迪现有计算引擎上跑 10 个已完成项目的"重算"（用原输入参数），记录每次 `run_calc` → `get_calc_result` 的端到端耗时，取 P50 和 P95。如果 P95 > 15 分钟则需要重新评估"30 分钟出草案"的承诺 |

#### Tiger 4: 销售认为"又多了一个工具"而非"替代了工作"

| 维度 | 内容 |
|------|------|
| **根因链** | 销售已习惯打电话给技术部口头沟通需求 → 系统要求上传文件+填对话框 → 操作步骤反而比"打个电话"多 → 销售觉得"不如直接找人" → 使用率低 → Agent 无数据积累 → 恶性循环 |
| **Kill Criteria** | Phase 1 上线后 14 天内，销售主动使用次数 < 5 次（排除测试/演示），或首次使用后 7 天内无第二次使用 |
| **最廉价验证测试** | 上线前，找 3 名销售做"纸上模拟"：给他们一个假需求，让他们分别用"打电话找技术部"和"通过飞书机器人上传文件+对话补全"两种方式完成，记录每种方式的耗时和主观感受。如果 > 2/3 销售认为"机器人方式更麻烦"，假设失败 |

### 📄 Paper Tigers（看起来危险但实际可控）—— 不用太担心

#### Paper Tiger 1: LLM 幻觉导致报价数字错误

**为什么可控**：报价的核心数字（价格、损耗值、物料单价）走**规则引擎计算**，不依赖 LLM 生成。LLM 只负责需求解析、对话交互和文档生成。即使 LLM 出错，也只影响"自然语言描述"，不影响核心计算数字。加上 Phase 1 强制 HITL，错误数字过不了审核关。

#### Paper Tiger 2: 客户数据泄露/安全合规

**为什么可控**：系统设计为**私有化部署**，数据不出企业内网。已有 Agent Runtime 经过法拉迪安全审计。物料价格等敏感数据走内部数据库，不调用外部 LLM API 处理敏感字段。Phase 1 不对接外部 ERP，攻击面小。

#### Paper Tiger 3: 多品种小批量太杂，Agent 无法泛化

**为什么可控**：Phase 1 不追求泛化，只覆盖"已有历史计算项目的相似场景"。匹配不到就明确提示"无合适历史参考，请联系技术专家"，回退到人工流程。用"能做的做好，不能做的诚实告知"策略，避免强行出低质量方案。

---

### 🐘 Elephants（低概率但致命）—— 需要 Plan B

#### Elephant 1: 法拉迪电磁计算引擎在 Phase 1 期间未完成 API 化

| 维度 | 内容 |
|------|------|
| **概率** | 低（已有合同，且 CLI 工具已可调用） |
| **影响** | 致命——参数优化环节完全无法执行，方案只能做到"匹配+手动调整" |
| **Plan B** | 降级方案：Phase 1 先跳过自动参数优化，改为"匹配历史项目 + 差异分析标注 + 专家手动调参"。保持 Agent 其他环节（需求解析→匹配→BOM→报价）正常运行。电磁计算引擎 API 化完成后自动升级 |

#### Elephant 2: 法拉迪核心技术人员离职，项目断档

| 维度 | 内容 |
|------|------|
| **概率** | 低（已签约，团队稳定） |
| **影响** | 致命——知识库回溯教学中断，计算引擎对接无人协调 |
| **Plan B** | ① 项目启动前录制至少 10 个标杆案例的完整视频讲解（含屏幕录制），作为知识库冷启动保底。② 所有 API 接口文档化、代码仓库化，确保任何 Python 开发者可在 2 天内接手 Tool Executor 集成工作。③ 物料价格库设计为独立模块，不强依赖特定人员 |

## 5.2 Red Team 攻击 —— 攻击五大承载假设

---

### 攻击假设 1: "30 分钟出草案"

| 维度 | 内容 |
|------|------|
| **攻击问题** | "30 分钟"是端到端时间还是纯 Agent 处理时间？销售上传文件后去干别的事算不算？对话补全缺失参数要几个来回？如果客户说"我也不知道绝缘等级，你帮我定"，Agent 能自己决策吗？ |
| **为什么重要** | 这是核心价值主张。如果实际体验是"上传→等 5 分钟→收到 3 个问题→等销售回复→再等 10 分钟→又来 2 个问题"，真实体感可能是 2-3 小时（含销售响应间隙），与"30 分钟"严重不符 |
| **最廉价验证** | 用 5 个真实历史项目的需求描述（脱敏），人工模拟整个流程：自己扮演 Agent 执行每一步，严格计时。注意区分"Agent 处理时间"和"含等待的墙钟时间" |
| **Kill Criteria** | 在模拟测试中，如果"Agent 处理时间"（不含销售响应间隙）P50 > 15 分钟，或需要 > 3 轮对话补全才能出草案，则假设不成立。如果需要 > 5 轮对话补全，则"30 分钟"承诺需降级为"2 小时内" |

---

### 攻击假设 2: "50-100 份历史项目即可起步"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 50-100 份是按项目数量算还是按覆盖场景数算？如果 100 份全是同容量段（比如都是 1000kVA 以下），遇到 3000kVA 项目怎么办？历史项目数据格式统一吗？有多少是"有完整计算结果"的，有多少只有"最终报价单"？ |
| **为什么重要** | 数据质量决定系统下限。如果法拉迪 100 份历史数据中只有 30 份有完整电磁计算结果，其余只有 PDF 报价单，那 Agent 的"导入计算数据"能力只能用在 30% 的匹配上 |
| **最廉价验证** | 让法拉迪提供一份历史项目清单（项目编号+容量段+电压等级+是否有完整计算结果），画一个参数覆盖矩阵，检查 Top 10 高频需求场景的覆盖率。如果 < 60%，需要调整冷启动策略 |
| **Kill Criteria** | 历史计算项目中，Top 10 高频参数组合（容量段×电压×冷却方式）覆盖率 < 50%，或"有完整计算结果"的项目 < 30 份 |

---

### 攻击假设 3: "销售会用飞书机器人"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 销售当前最习惯的工具是什么？是飞书、微信、电话、还是 Excel？"发消息给机器人上传文件"这个操作对非技术人员友好吗？如果销售在客户现场用手机，文件上传体验如何？ |
| **为什么重要** | 再好的 Agent，如果销售不用就是零价值。飞书机器人是"销售入口"，它的使用门槛直接决定用户采纳率 |
| **最廉价验证** | 做一个"假机器人"：在飞书群发一个固定消息"请上传客户需求文件"，销售回复文件后，5 分钟内手动发一段"解析结果"（自己编的就行），观察销售是否愿意配合这个流程。如果连"假装的"流程都无人响应，真实版更不可能成功 |
| **Kill Criteria** | 10 名目标销售中，< 3 人在 2 周内主动使用假机器人上传过文件（含演示引导），或使用后明确表示"太麻烦不如打电话" |

---

### 攻击假设 4: "专家每周 2-3 小时回溯教学"

| 维度 | 内容 |
|------|------|
| **攻击问题** | 专家的日常 KPI 是什么？回溯教学是否纳入考核？如果一个专家正在赶一个紧急项目，"2-3 小时回溯历史项目"是优先还是延后？ASR→结构化→确认这个流程，专家觉得"有用"还是"额外负担"？ |
| **为什么重要** | 知识库是 Agent 的"大脑"。如果专家不持续灌入案例，Agent 能力永远停在冷启动水平。这是整个系统的长期竞争力来源 |
| **最廉价验证** | 第 1 周就安排 1 次试录实验，让专家翻 2 个历史项目口述评审逻辑，测试完整流程的摩擦系数。同时与法拉迪管理层沟通，确认是否将"知识库贡献"纳入专家绩效考核 |
| **Kill Criteria** | 试录实验中，专家明确表示"太浪费时间"或"我不确定该说什么"的比例 > 50%，或第 4 周实际累计录入 < 10 个高质量案例 |

---

### 攻击假设 5: "电磁计算引擎 API 足够快"

| 维度 | 内容 |
|------|------|
| **攻击问题** | "足够快"的定义是什么？1 秒？10 秒？10 分钟？当前 `run_calc` 的 P50/P95 延迟是多少？是否支持异步提交+轮询？并发计算能力如何（如果 5 个销售同时下单）？超时阈值设多少？ |
| **为什么重要** | 电磁计算是方案优化的核心环节。如果这一步慢了，其他所有步骤的加速都失去意义——"30 分钟出草案"的承诺直接破产 |
| **最廉价验证** | 在法拉迪测试环境，用 10 个不同复杂度的历史项目跑 `run_calc`，记录端到端耗时（提交→结果可取）。按复杂度分 3 档（简单/中等/复杂），分别记录 P50/P95 |
| **Kill Criteria** | 中等复杂度项目的 `run_calc` P95 > 10 分钟（异步模式下从提交到结果可取），或复杂项目 > 20 分钟 |

## 5.3 用户故事（User Stories）

---

### US-1: 销售 —— 上传需求文件自动解析

**As a** 销售人员, **I want** 在飞书机器人中上传客户发来的需求文件（PDF/Word/Excel），**so that** 系统自动提取技术参数并结构化，我不需要手动转述或翻译客户原始文件。

**验收标准（AC）:**
1. 支持 PDF、Word、Excel、纯文本消息四种输入格式
2. 上传后 ≤ 60 秒返回结构化参数提取结果
3. 提取结果包含：产品类型、容量、电压、冷却方式、特殊要求等关键字段
4. 每个提取字段标注置信度（高/中/低），低置信度字段标黄提示
5. 错误的提取结果可由销售在对话中直接修改

---

### US-2: 销售 —— 对话式补全缺失参数

**As a** 销售人员, **I want** 当需求文件中缺少某些参数时，Agent 以自然语言对话形式问我，**so that** 我无需理解技术术语含义就能补全信息，直接转发客户原话或用大白话回复即可。

**验收标准（AC）:**
1. 识别出缺失参数后 ≤ 30 秒发起追问
2. 追问使用自然语言（非术语），例如："客户有提到安装在室内还是室外吗？"而非"请确认 IP 防护等级"
3. 销售可用自然语言回复，Agent 自动提取填入对应字段（如销售说"室外，下雨的"，Agent 自动填入 IP54）
4. 最多 3 轮对话完成参数补全（超过 3 轮标红提示需专家介入）
5. 补全过程中可随时说"就用默认值"跳过，Agent 自动填充行业默认值并标注

---

### US-3: 销售 —— 查看匹配到的历史方案

**As a** 销售人员, **I want** 看到 Agent 匹配到的最接近的历史项目及其与当前需求的差异对比，**so that** 我能快速判断方案是否靠谱，必要时调整需求或选择不同匹配结果。

**验收标准（AC）:**
1. 返回 Top 3 匹配结果，每个显示匹配度百分比
2. 每个结果以表格形式展示关键参数对比（历史值 vs 当前需求）
3. 差异项高亮标注（容量不同/电压不同/冷却方式不同等）
4. 销售可选择"用这个方案"或"换一个匹配结果"
5. 匹配结果 ≤ 10 秒返回

---

### US-4: 专家 —— 审核 Agent 生成的报价草案

**As a** 技术专家, **I want** 在 Web 控制台看到 Agent 生成的完整报价草案（含需求解析、匹配项目、计算结果、BOM、报价明细），**so that** 我能在 ≤ 10 分钟内确认或驳回，确保报价准确性和技术可行性。

**验收标准（AC）:**
1. 审核页面一次性展示全部信息：需求参数、匹配项目、电磁计算结果、BOM、报价明细
2. 支持逐项审核和批注：专家可在任意字段旁添加批注
3. 一键"通过"或"驳回"，驳回必须填写原因
4. 专家修改的字段自动标注"专家修正"，用于后续 Agent 学习
5. 审核操作耗时 ≤ 10 分钟（通过界面设计保证关键信息一目了然）

---

### US-5: 业务经理 —— 查看报价统计和转化率

**As a** 业务经理, **I want** 看到所有报价的统计仪表盘（报价数量、平均响应时间、通过率、驳回原因分布），**so that** 我能评估系统效果并做出资源调配决策。

**验收标准（AC）:**
1. 仪表盘展示：累计报价数、平均生成时间、平均审核时间、通过率、Top 5 驳回原因
2. 支持按时间范围（日/周/月）筛选
3. 支持按销售/产品类型/客户分组查看
4. 数据实时更新（≤ 5 分钟延迟）
5. 支持导出报表（Excel/PDF）

---

### US-6: 系统管理员 —— 管理物料价格库

**As a** 系统管理员, **I want** 通过 Web 控制台导入/更新物料价格数据（支持 Excel 批量导入），**so that** 报价中的物料成本始终反映最新市场价。

**验收标准（AC）:**
1. 支持 Excel/CSV 批量导入物料价格数据
2. 导入时自动校验：料号重复提醒、价格异常值（偏差 > 50%）标黄
3. 导入后 ≤ 1 分钟内新价格生效
4. 保留历史版本，支持回滚到任意历史价格
5. 支持按料号/类别/供应商查询当前价格

---

### US-7: 专家 —— 回溯教学录入历史案例

**As a** 技术专家, **I want** 翻开一个历史项目，边看边口述评审逻辑和决策理由，系统自动结构化入库，**so that** 我不需要花时间写文档，但我的经验能被 Agent 学习。

**验收标准（AC）:**
1. 支持"选择历史项目→开始录制"的简单操作流程
2. 语音录制 → ASR 转文字 → LLM 结构化为"需求-方案-决策"三元组，全程 ≤ 2 分钟完成一个案例
3. 结构化结果供专家确认/修改后入库
4. 入库时自动打标签（产品类型、场景、难度等级）
5. 一个 30 分钟的录制session可完成 ≥ 10 个案例的录入

---

### US-8: 销售 —— 客户修改需求后自动更新报价

**As a** 销售人员, **I want** 当客户修改需求时（如改容量、改电压），我能告诉 Agent 哪里变了，Agent 自动更新方案和报价，**so that** 我不需要重新走一遍全流程。

**验收标准（AC）:**
1. 销售用自然语言描述变更（如"客户要把容量从 1000 改成 1250"），Agent 自动识别变更项
2. 仅对变更部分重新计算，复用未变更部分的数据
3. 更新后的报价与原报价差异一目了然（哪些变了、变了多少）
4. 更新耗时 ≤ 原生成时间的 30%（因为只重算差异部分）
5. 保留历史版本，可对比查看

---

### US-9: 专家 —— 查看计算结果的置信度和依据

**As a** 技术专家, **I want** 在审核报价时能看到 Agent 方案的置信度评分和决策依据（匹配了哪个历史项目、哪些参数做了调整、调整理由），**so that** 我能高效判断需要重点关注哪些部分，而非从头审核。

**验收标准（AC）:**
1. 每个方案展示综合置信度评分（基于匹配度+参数覆盖度+历史类似方案成功率）
2. 标注每个关键参数的来源：来自哪个历史项目、是否被 Agent 调整、调整理由
3. 低置信度字段（< 60%）自动标红，提示专家重点关注
4. 专家点击任意字段可查看完整的决策链路
5. 支持"一键折叠/展开"，专家可选择只看标红项

---

### US-10: 系统管理员 —— 监控 Agent 运行健康状态

**As a** 系统管理员, **I want** 看到 Agent 各环节（需求解析、方案匹配、计算、BOM、报价）的运行状态和耗时，**so that** 我能及时发现和定位问题。

**验收标准（AC）:**
1. 实时展示每个 Agent 任务的进度和当前阶段
2. 记录每个环节的耗时（P50/P95），自动标红超时任务
3. 记录每个 Tool 的调用成功率和平均响应时间
4. 支持查看 Celery 异步任务队列深度和 Worker 状态
5. 异常事件（计算超时、API 调用失败）自动告警

### 3.2 各步骤详解

| 步骤 | Agent 动作 | 输入 | 输出 | 耗时 |
|:---:|----------|------|------|:----:|
| **① 需求解析** | LLM 理解自然语言/图纸/规格书，提取结构化需求参数，对话式补全缺失信息 | 客户需求文件（PDF/Word/Excel/消息） | 结构化需求清单 + 缺失项追问 → 对话补全 | 1-3 分钟 |
| **② 方案匹配** | 从已完成计算的历史项目中匹配最接近方案，导入其计算数据作为起点 | 结构化需求 + 历史项目计算数据库 | 最接近的已完成项目数据 + 差异分析表 | 2-5 分钟 |
| **③ 参数优化** | 基于差异点自动修改参数，调用电磁计算引擎运行优化计算，生成定制方案 | 已导入项目数据 + 差异点 | 优化计算完成的定制技术方案 | 5-10 分钟 |
| **④ BOM 生成** | 方案 → 物料清单，关联物料价格库，推荐替代料 | 技术方案 | BOM 清单 + 单价 + 供应商信息 | 3-5 分钟 |
| **⑤ 成本核算** | 物料成本 + 加工工时 + 人工 + 管理费分摊 + 目标利润 | BOM + 工艺知识库 | 成本价 + 建议报价 | 2-3 分钟 |
| **⑥ 报价输出** | 生成标准格式报价单 + 技术方案附件，进入审批流 | 全部信息 | 报价单（PDF/Word）+ 方案附件 | 1-2 分钟 |

**总耗时：15-30 分钟 vs 传统 7-15 天 — 压缩 50-100 倍**

### 3.3 各模块详细设计

#### ① 需求解析模块

```
输入示例："1250kVA 方形干式变压器，35kV/0.4kV，工业园区，空载损耗≤国标85%，AN冷却，户外IP54"

Agent 动作：
  1. LLM 结构化提取 →
     {
       产品类型: "方形干式变压器",
       容量: 1250,           // kVA
       高压: 35,             // kV
       低压: 0.4,            // kV
       冷却方式: "AN",
       防护等级: "IP54",
       应用场景: "工业园区",
       损耗约束: { 空载损耗: "≤国标×0.85" },
       截面类型: "square"
     }

  2. 缺失信息识别 →
     ⚠ 未提及: 绝缘等级 | 安装方式 | 海拔 | 尺寸约束 | 通讯协议
     → 以对话形式逐项向销售/客户确认，销售可在对话框中直接填写回复
     → 每次对话自动更新结构化需求，直到所有关键参数完备

  3. 参数校验 → 对接已有 Schema（参见法拉迪 SRS §4 输入规格）
     - 容量/电压/频率不可为空
     - a/b/r 满足几何可制造约束
     - AN 模式下 AF 字段可为空
```

**关键设计：不再只是生成问题清单，而是通过对话式交互引导销售逐项补全缺失信息。** 销售无需理解技术参数含义，系统以自然语言提问，销售可直接回复或转发客户原话，Agent 自动提取填入。

#### ② 方案匹配模块

**核心思路：不只要找到"像"的方案，要找到"已经算过"的项目，直接导入其计算数据作为新方案的起点。**

```
数据来源：已完成电磁计算的历史项目（而非仅归档的 PDF 报价单）
  每个项目包含：输入参数 + 电磁计算结果（铁芯截面、绕组数据、损耗值、
              温升、阻抗等）+ BOM + 最终报价 + 决策记录

匹配策略（多路召回 + 重排序）：

路1：参数精确匹配 → 同容量段 + 同电压等级 + 同冷却方式 + 同绝缘等级
       → 直接匹配法拉迪计算数据库中的已完成项目
路2：语义向量检索 → 找需求描述最接近的历史项目（客户行业、应用场景）
路3：客户维度 → 同一客户之前做过的项目

重排序：
  综合得分 = 0.35 × 参数精确匹配度 + 0.25 × 语义相似度
           + 0.20 × 计算状态加分（已完成计算 > 仅方案设计）
           + 0.10 × 时间衰减 + 0.10 × 客户相关性

关键动作：找到最优匹配项目后，自动导入其计算数据到当前项目
  - 导入：输入参数、电磁计算结果、BOM 结构
  - 标记：与当前需求的差异点（容量不同/电压不同/损耗要求不同等）
  - 差异可视化：高亮哪些参数需要重新计算

输出：最接近的已完成项目 + 完整计算数据 + 差异对比表
  ┌────────┬──────────┬──────────┬──────────┬────────┐

  │ 数据导入 │ ✅ 采纳   │ —        │ ✅ 采纳   │  ——    │
  └────────┴──────────┴──────────┴──────────┴────────┘
```

#### ③ 参数优化模块

**核心思路：不只是改参数，而是调用电磁计算引擎重新跑优化计算，得到真正可用的技术方案。**

```
Agent 动作：

1. 差异分析 → 对比当前需求与导入项目数据的差异
   示例：
   - 容量 1000→1250kVA → 铁芯截面需增大，绕组匝数需重算
   - 损耗从标准→低15% → 可能需要换材料牌号或增大铁芯
   - 防护等级变更 → 外壳/密封方案调整

2. 参数修改 → 基于差异自动更新输入参数
   - 对接法拉迪 create_scheme / update_scheme_params
   - 自动填充默认值（未指定的参数沿用原项目或取行业默认）

3. 优化计算 → 调用电磁计算引擎运行计算
   - 对接已有 run_calc 能力，提交计算任务
   - 粗算（快速迭代）→ 验证方案可行性
   - 精算（最终确认）→ 输出完整电磁方案数据
   - 异步执行（Celery），Agent 轮询进度

4. 结果验证 → 检查计算结果是否满足客户约束
   - 损耗是否达标？温升是否在范围内？阻抗是否合理？
   - 不达标 → 自动调整参数重算（最多 3 轮），或标记需人工介入

5. 方案输出 → 生成定制化技术方案
   - 完整电磁计算结果（铁芯/绕组/绝缘/冷却/结构）
   - 关键性能指标（损耗/温升/阻抗/效率）
   - 与导入项目的差异说明
```

**关键设计：方案定制不再是简单的参数复制粘贴，而是真正的工程优化计算。** 法拉迪已有的电磁计算引擎是核心资产——Agent 的职责是"判断改什么参数"，计算引擎的职责是"算出具体结果"。

```
物料价格库                   ├─ 数量
  (元器件/原材料/标准件)      ├─ 单价 ← 关联
                              ├─ 供应商 ← 关联
```

#### ⑤ 成本核算模块

```
成本核算公式（Agent 内部逻辑）：

总成本 = Σ(物料单价 × 数量)              # BOM 成本
       + Σ(工时 × 工时费率)              # 加工成本
       + 管理费用 × 分摊系数              # 管理成本
       + 检测费用                        # 测试成本
       + 包装运输                        # 物流成本

报价 = 总成本 × (1 + 目标利润率)
     × 客户折扣系数                     # 大客户/新客户/战略客户
     × 交期加急系数                     # 加急单加价

数据源及更新频率：
| 数据源 | 内容 | 更新频率 |
|--------|------|---------|
| 物料价格库 | 元器件/原材料/标准件价格，含供应商报价 | 每周/每月 |
| 工艺知识库 | 加工工时标准、装配工时、测试工时 | 季度 |
| 成本模型 | 物料成本+加工费+人工+管理费分摊+利润率 | 每年 |
| 供应商数据 | 价格/交期/MOQ/账期 | 实时/每周 |
```

#### ⑥ 报价输出模块

```
输出包：
  ├─ 报价单（PDF）       ←  标准模板，含公司抬头、有效期、付款条件
  ├─ 技术方案书（PDF）    ←  含参数表、方案说明、关键指标
  ├─ 方案附件包           ←  可选：三维预览图、BOM 简表、参考案例
  └─ 审批记录             ←  自动进入审批流（技术负责人→商务负责人）
```

## 九、关键设计决策（ADR）

### ADR-001：全链路覆盖 + 重在复用已有计算数据

**决策**：Agent 覆盖"需求解析→方案匹配与数据导入→参数优化→BOM生成→成本核算→报价输出"全链路。方案匹配环节优先匹配**已完成电磁计算**的历史项目，直接导入其输入参数、计算结果和 BOM 结构作为新方案的起点，而非仅做语义检索推荐。

**理由**：客户要的是"报价单"，不是"评审结论"。更重要的是，法拉迪已有大量已完成电磁计算的历史项目数据——这些数据包含了精确的铁芯截面、绕组参数、损耗值等工程计算结果，远比 PDF 报价单有价值。导入这些数据后只需对差异部分重新计算，大幅提升方案准确性和效率。

### ADR-002：复用现有 Agent Runtime，不另起炉灶

**决策**：报价 Agent 基于法拉迪已有的 Planner/slot_llm/qa_llm/Tool Executor 架构扩展，新增 7 个报价相关 Tool，对接已有的电磁计算/BOM/出图能力。

**理由**：已有 Agent Runtime 经过多轮迭代和评测验证（26 轮多轮评测，20 正确），架构稳定。新增 7 个报价相关 Tool（含对话补全、已完成项目检索、数据导入、参数优化等），对接已有的电磁计算/BOM/出图能力。复用而非重建可节省 60-70% 工程量。

### ADR-003：对法拉迪增量交付，不做轨物自用验证

**决策**：直接对法拉迪交付，跳过轨物自用验证环节。在法拉迪已有 Agent 底座上做增量扩展。

**理由**：法拉迪是已有签约客户，Agent Runtime / MCP Server / BOM 引擎 / 计算引擎已在建设中。报价/方案智能体复用这些资产，是现有合同范围的自然延伸，无需另做独立验证。

### ADR-004：人机关系 — HITL 渐进放松

**决策**：Phase 1 强制 HITL（所有报价必须人工确认），Phase 2 高置信度场景试点自动通过，Phase 3 根据成交率数据动态调整自动化程度。

**理由**：报价错误成本极高（亏本接单或高价丢单），而且制造业报价涉及大量未编码的隐性知识。必须先用 HITL 积累足够信任和准确率数据。

### ADR-005：知识表示 — 案例图谱而非文件库

**决策**：历史项目存储为"需求-方案-BOM-报价-决策"全链路案例节点，每个字段带"为什么"注释和决策理由，而非原始 PDF 归档。

**理由**：文件库只能搜文件名，案例图谱可以按参数向量匹配。带决策原因（为什么采纳/否决/定价策略）才能支持未来的智能定价优化。

## 十、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|:----:|------|------|
| 历史报价数据质量差 | 高 | 高 | 先做数据清洗+标准化；Phase 1 只要 50-100 份即可起步 |
| 已完成计算项目数据不足 | 中 | 高 | Phase 1 最低要求 30-50 份已完成电磁计算的项目；不足则先从现有项目开始积累，同时支持仅基于报价单的降级模式 |
| 报价逻辑复杂（非标件多） | 高 | 高 | 先覆盖"80% 标准件 + 20% 定制"，极端定制仍由人工处理 |
| 物料价格波动导致成本不准 | 中 | 中 | 价格库设计周/月级更新机制；报价单标注"价格有效期 30 天" |
| 专家回溯时间无法保障 | 中 | 中 | 降低期望至 1h/周；聚焦 Top 10 高频场景；法拉迪专家已确认配合 |
| LLM 幻觉导致报价错误 | 中 | 高 | HITL 强制审核；核心数字（价格、损耗值）走规则引擎不依赖 LLM |
| 客户信息敏感 | 中 | 中 | 私有化部署，数据不出企业；租户隔离 |
| 与 ERP 系统对接困难 | 中 | 中 | Phase 1 独立运行不依赖 ERP；Phase 2 预留标准 API |

## 十一、范围边界

### Phase 1 明确包含
- 文件驱动的需求解析（PDF/Word/Excel/消息）
- 对话式交互补全缺失参数
- 已完成计算的历史项目匹配 + 计算数据导入
- 参数优化（差异分析 + 调用电磁计算引擎运行优化计算）
- BOM 生成（对接已有 BOM 引擎）
- 成本核算（物料+加工+管理费，简单利润测算）
- 报价单生成（标准模板 PDF/Word）
- 专家审核控制台（HITL）

### Phase 1 明确不包含
- 深度 ERP/PLM 双向同步（仅预留接口）
- 供应商实时价格动态查询
- 竞品报价分析
- 成交率追踪和定价策略优化
- 全自动无人值守报价（必须 HITL）
- 油浸式/异形非标产品的泛化处理
- 从零创建无历史参考的全新方案（Phase 1 依赖至少 1 个可参考的已完成项目）

### 后续阶段触发条件
- 报价准确率（HITL 修改率）< 10% → 试点高置信度自动通过
- 案例库 > 500 个高质量全链路案例 → 启动定价策略优化
- Phase 1 法拉迪验收通过 → 启动 Phase 2 智能增强

## 十二、vs 传统方式对比

| 维度 | 传统方式 | Agent 方式 | 提升 |
|------|---------|----------|------|
| **响应速度** | 7-15 天 | 30 分钟 - 2 小时 | 50-100 倍 |
| **人力投入** | 2-3 人（技术+商务+审批） | 1 人审核确认 | 减少 60-70% |
| **方案一致性** | 不同人出不同方案，不同价 | 标准化输出 | 100% 一致 |
| **知识复用** | 靠个人记忆，经常找不到 | 自动匹配已完成项目，导入计算数据 | 零遗漏，直接复用工程数据 |
| **计算质量** | 每次从零手算 | 基于已验证的工程计算数据优化 | 准确率大幅提升 |
| **客户体验** | 等待焦虑 | 快速响应 → 专业印象 | 转化率提升 |
| **报价准确度** | 依赖经验，波动大 | 数据驱动，可追溯 | 误差可收敛 |
